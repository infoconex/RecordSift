# FR-026 — Import records into strongly typed objects

**Requirement:** [FR-026](../../requirements/functional.md)  
**Tracking issue:** [#27](https://github.com/infoconex/RecordSift/issues/27)  
**Priority:** Must  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Applications want usable .NET domain objects rather than raw strings from every file format.

## Functional requirement

**RecordSift shall:** Materialize imported, validated data into instances of a declared .NET record type.

## Inputs and outputs

- **Inputs:** Schema/property mappings, successfully converted field values and target CLR type.
- **Outputs:** Typed instances for valid records or actionable binding/conversion diagnostics.

## Functional rules

- Use one common typed output contract for supported import formats.
- Do not return partially invalid objects as accepted records.
- Maintain source order for accepted instances.
- Avoid silently discarding conversion/mapping failures.

## Dependencies and scope

- **Related requirements:** [FR-009](FR-009.md), [FR-010](FR-010.md), [FR-011](FR-011.md), [FR-027](FR-027.md), [FR-028](FR-028.md).
- **Boundary:** This is about materializing records; source parsing and reporting are independently tracked.

## Open design decisions

Determine supported constructors, setters, immutable models and nullability semantics.

## Acceptance scenarios

### FR-026-SC01 — Materialize a declared generic record type

**Given** an import schema maps source columns to a .NET customer model,  
**When** valid rows are processed,  
**Then** instances of that type contain correctly converted values.

### FR-026-SC02 — Reject incompatible destination mapping

**Given** a destination property cannot receive the declared converted value,  
**When** a record is processed,  
**Then** a structured mapping/conversion failure is returned rather than a silently corrupted object.
