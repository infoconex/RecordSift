# NFR-003 — Do not require Microsoft Excel installation

**Requirement:** [NFR-003](../../requirements/non-functional.md)  
**Tracking issue:** [#43](https://github.com/infoconex/RecordSift/issues/43)  
**Priority:** Must — release 0.1 quality requirement (later-platform scenarios remain future milestones).  
**Verification status:** Planned — no executable checks have run.

## NFR-003-SC01 — Read XLSX without Excel

**Given** a clean Windows test runner has no Microsoft Office installed,  
**When** a supported XLSX fixture is imported,  
**Then** records and diagnostics are produced successfully.

## NFR-003-SC02 — Avoid Office automation

**Given** the Excel reader is reviewed and its clean-runner integration test runs,  
**When** the workbook is processed,  
**Then** the implementation has no COM automation or Excel executable dependency.

## Verification notes

**Observed evidence:** [Windows PR #41185182932](https://github.com/infoconex/RecordSift/actions/runs/41185182932) passed 282/282 NUnit tests; its Office-free preflight observed no Excel COM registration or executable and rejected no forbidden Office dependency references. Dedicated NFR-003 runs passed 2/2. [Documentation #41185183014](https://github.com/infoconex/RecordSift/actions/runs/41185183014) passed. Both scenarios are Automated in the traceability matrix; this document retains the repository-required planning label above.

The Windows 2022 CI runner first checks that Excel's COM ProgID is unregistered, `EXCEL.EXE` is absent from PATH and common Office installation directories, and production source/project metadata contains no Office automation/PIA references. It then executes two real ExcelDataReader-based XLSX acceptance tests, including typed mapping and raw worksheet port behavior. This establishes no Excel dependency on the tested runner; it does not inspect all possible nonstandard installation directories or certify other Windows images. Package restore occurs before the import tests and does not entail runtime Office licensing.

Follow the [testing strategy](../../testing/strategy.md). Record the executable test or reviewed procedure and observed evidence separately for each scenario in [traceability](../../testing/traceability.md). Scenarios for future modernized targets cannot be declared verified on the initial .NET Framework baseline.
