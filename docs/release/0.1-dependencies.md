For the older Microsoft runtime packages, NuGet's **License Info** link resolves to the .NET CoreFX [MIT LICENSE.TXT](https://github.com/dotnet/corefx/blob/master/LICENSE.TXT); this explains why some version-specific NuGet pages display a generic license link rather than an explicit SPDX badge.

The internal candidate's `packaging/RecordSift.nuspec` specifies exactly these versions with bracketed dependency ranges, and `scripts/verify_clean_consumer.ps1` checks that the independent Windows installation contains all eleven specified package versions. The NuGet package contains the five RecordSift net48 DLLs and their XML docs, **not** vendor DLLs under the RecordSift identity. Installing dependencies from NuGet does not exempt the distributor or downstream users from the actual package license conditions.

## RecordSift project license: owner approved, pending release authorization

On 2026-10-31 the repository/release owner approved **MIT** as the license for RecordSift-owned source and assemblies with **Copyright (c) 2026 Infoconex**, addressing the licensing decision in [issue #186](https://github.com/infoconex/RecordSift/issues/186).

The approved text is committed in the root [LICENSE](../../LICENSE), and `packaging/RecordSift.nuspec` declares `<license type="expression">MIT</license>`. The candidate package includes exact copies of `LICENSE` and [THIRD-PARTY-NOTICES.md](../../THIRD-PARTY-NOTICES.md), verified by the package-build and clean-installed-consumer scripts. The MIT license **grants rights subject to its conditions**; public GitHub visibility alone was not sufficient before this approval.

All eleven independently installed runtime NuGet dependencies are identified above. CsvHelper's license expression is **MS-PL OR Apache-2.0**, and the ten other packages use MIT, including ExcelDataReader. Vendor packages are resolved independently from NuGet, not repackaged into the RecordSift distribution. Preserve notices required by applicable upstream terms if redistributing any vendor binaries separately. Reassess all license details when upgrading versions.

**Release status:** This approval removes the lack-of-project-license blocker but does **not** approve promotion to `main`, publication to nuget.org, creation of public GitHub releases or tags, or a stable 0.1.0 package. Those steps require separate release-owner authorization and validation of the exact stable artifact.

## Vulnerability and operational evidence

The release-branch Windows run [#41237118017](https://github.com/infoconex/RecordSift/actions/runs/41237118017) passed the pinned-manifest and NuGet advisory audit after packaging and consumer work. CI rejects vulnerability warning codes NU1900–NU1905. This is evidence at that run, not a permanent absence-of-vulnerabilities claim. Repeat on the precise release promotion artifact, with the advisory service reachable.

Existing tests cover bounded hostile input, Office-free XLSX, no-service runtime processing, deterministic reporting and source-path redaction. Review the final repository contents and distribution artifacts for credentials and sensitive test fixtures before publication. Arbitrary caller-supplied diagnostic identifiers and field/worksheet metadata cannot be presumed nonsensitive.

## Build/test-only tools

NUnit 3.14.0 and NUnit.ConsoleRunner 3.17.0 are developer/test dependencies, not included in the runtime distribution package. Their licenses and redistribution obligations would need a separate check only if those tools are themselves distributed.
