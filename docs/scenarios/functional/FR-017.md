# FR-017 — Validate required fields

**Requirement:** [FR-017](../../requirements/functional.md)  
**Tracking issue:** [#9](https://github.com/infoconex/RecordSift/issues/9)  
**Priority:** Must  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Incomplete mandatory business data must not enter accepted output records.

## Functional requirement

**RecordSift shall:** Validate fields marked required and identify missing or unacceptable values.

## Inputs and outputs

- **Inputs:** A field value, requiredness policy and source provenance.
- **Outputs:** A field-specific required-value diagnostic or a successful requiredness check.

## Functional rules

- Treat missing required data as a record-validation error.
- Identify both logical record and failing schema field.
- Do not report errors for nonempty valid required values.
- Apply any whitespace/empty policy consistently with optional-field semantics.

## Dependencies and scope

- **Related requirements:** [FR-012](FR-012.md), [FR-028](FR-028.md), [FR-029](FR-029.md).
- **Boundary:** Required source column absence is schema-binding behavior rather than a record-level missing-value failure.

## Open design decisions

Define whitespace normalization, nullable required values and first-error ordering.

## Acceptance scenarios

### FR-017-SC01 — Reject missing required values

**Given** a required field is missing or blank according to its policy,  
**When** field validation runs,  
**Then** a required-value diagnostic identifies that field and record.

### FR-017-SC02 — Accept an explicitly present value

**Given** a required field contains a valid nonempty value,  
**When** field validation runs,  
**Then** the required-field rule does not reject the row.
