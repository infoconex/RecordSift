# FR-038 — Export validation errors as CSV

**Requirement:** [FR-038](../../requirements/functional.md)  
**Tracking issue:** [#39](https://github.com/infoconex/RecordSift/issues/39)  
**Priority:** Should  
**Verification status:** Planned — retained scenario-planning metadata only; observed executable acceptance is recorded in [traceability](../../testing/traceability.md).

## Purpose

Some integrations need a portable, deterministic list of invalid field and source diagnostics that can be reviewed without reopening the imported source.

## Functional requirement

**RecordSift shall:** Export existing validation diagnostics to CSV text with stable field headings, reliable escaping and sanitized metadata.

## Inputs and outputs

- **Inputs:** An existing typed import result and an optional CSV delimiter setting.
- **Outputs:** A CSV text report containing a fixed header followed by ordered escaped diagnostic rows; header-only output when no diagnostics exist.

## Functional rules

- Use correct quoting and doubled quotes for field values that contain delimiters, quotes, CR or LF; preserve original text on independent CSV re-reading.
- Do not re-read the source, include accepted record values, or serialize arbitrary caller result messages.
- Preserve source-level and record-level diagnostic order, stable field headings, logical rows and reliable source coordinates.
- Produce deterministic, culture-invariant CSV text and redact rooted path/file URI source identifiers by default.
- Preserve the error-free completed outcome with no invented errors in its header-only report.

## Dependencies and scope

- **Related requirements:** [FR-028](FR-028.md), [FR-036](FR-036.md), [FR-037](FR-037.md).
- **Boundary:** CSV diagnostic output only; no file delivery, Excel formatting, report templates, new imports or asynchronous processing.

## Open design decisions

Release 0.1 defines fixed heading order, comma by default with validated alternate delimiters, CRLF record separators, header-only zero-diagnostic behavior, and caller-owned text-to-bytes encoding. These are documented below and verified through the Infrastructure.Reporting adapter and independent CSV-reader acceptance tests.

### Public contract

`RecordSift.Infrastructure.Reporting.CsvImportResultSerializerAdapter` implements the existing `RecordSift.Application.Ports.Reporting.IImportResultSerializer` application port. Construct with no arguments for a comma delimiter, or supply a single delimiter character. `Serialize<T>(TypedImportResult<T>)` returns a .NET string; no file I/O, source processing, async, or new Domain contracts are introduced. A null result is rejected.

#### CSV wire shape

Exactly nine case-sensitive columns in this order:

```text
SourceId,Scope,Row,Field,Code,Message,Worksheet,PhysicalRow,PhysicalLine
```

- The first record is **always** the header, followed by exactly one record per source or record diagnostic in the original collection order.
- Every record ends with CRLF, including the header and last diagnostic. Embedded original CR/LF characters inside a value are preserved.
- Text containing the selected delimiter, a double quote, CR, or LF is enclosed in double quotes; embedded double quotes are doubled. This allows independent conforming CSV readers to reconstruct each value.
- `SourceId` is the same caller-owned opaque ID used in the existing JSON reporting adapter, including redaction to `source-redacted` for absolute paths and file URIs. It appears on each diagnostic row.
- `Scope` is `Record` or `Source`. `Row` is the invariant-culture one-based logical data row number for a record diagnostic; it is empty for source diagnostics. `Code` and `Message` preserve the registered Domain diagnostic code and its safe resource-backed message.
- Missing optional `Field`, `Worksheet`, `PhysicalRow` and `PhysicalLine` are **empty CSV fields**. Physical coordinates use invariant integer text; no placeholder text is invented.
- All `Completed`, `Failed`, `Stopped` and `Canceled` outcomes are supported. This is an **error-only diagnostic report**, so no status/summary/accepted-record columns are added, and serialization does not change the result or its meaning.

**Empty report policy:** for zero diagnostics, regardless of outcome, emit exactly the single header record ending in CRLF, and no fabricated diagnostic rows.

**Delimiter and encoding:** the default delimiter is comma; a caller may choose a different single character (e.g. semicolon, pipe, or tab). A double quote, CR, LF, NUL or other control character except tab is invalid. The interface returns text rather than bytes, so there is no misleading encoding option in the API. The caller chooses file encoding; **UTF-8 without BOM** is recommended when persisting the returned string. Non-ASCII characters are preserved in the returned string. This does not change source-import encoding configuration.

**Confidentiality and execution boundary:** the adapter never accesses or emits accepted CLR records, caller result status message, or original input values. Registered Domain diagnostics have fixed safe messages. As with JSON reporting, `SourceId` redacts rooted paths/file URIs; caller-selected field/worksheet identifiers and safe opaque IDs are metadata and are not generally scrubbed. Callers must not embed confidential record data in such metadata.

**This is a machine-interchange CSV contract, NOT a spreadsheet-safe export.** For exact round-trip fidelity, caller-controlled `SourceId`, `Field` and `Worksheet` values beginning with `=`, `+`, `-`, `@`, tabs, newlines, quotes or delimiters are preserved as CSV *data*. Correct CSV quoting ensures a conforming CSV parser reconstructs original fields, but does not neutralize spreadsheet formula interpretation (see [OWASP CSV Injection](https://owasp.org/www-community/attacks/CSV_Injection)). A user who needs a spreadsheet view must treat every imported column as **text** or apply and verify separate spreadsheet-specific neutralization before using a spreadsheet application. Such neutralization changes programmatic round-trip data and is **not** implemented silently in this version. Do not double-click untrusted CSV and assume CSV escaping makes formulas inert. The release owner explicitly accepted this residual risk for the release 0.1 machine-interchange CSV contract in [closed issue #200](https://github.com/infoconex/RecordSift/issues/200). This does **not** authorize tagging, GitHub Releases, NuGet publication, or other public distribution; publication still requires a separate owner GO.


## Acceptance scenarios

### FR-038-SC01 — Export escaped diagnostics

**Given** an import result contains errors with commas, quotes, or newlines in human-readable messages,  
**When** diagnostics are exported to CSV,  
**Then** stable headers and correctly escaped rows allow another CSV reader to reconstruct the messages.

### FR-038-SC02 — Export an error-free result

**Given** an import produces no diagnostics,  
**When** error-only CSV export is requested,  
**Then** output follows the documented empty-export policy and contains no invented errors.
