# FR-030 — Provide import processing summary

**Requirement:** [FR-030](../../requirements/functional.md)  
**Tracking issue:** [#31](https://github.com/infoconex/RecordSift/issues/31)  
**Priority:** Must  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Consumers need trustworthy totals for monitoring and deciding whether to accept an import.

## Functional requirement

**RecordSift shall:** Return a summary of processed, accepted and rejected rows plus warning/error diagnostic counts.

## Inputs and outputs

- **Inputs:** The completed import's accepted records and accumulated diagnostics.
- **Outputs:** Internally consistent summary counters and completion/failure state.

## Functional rules

- For completed imports, Processed equals Accepted plus Rejected.
- Count each rejected logical record once even if several errors occur.
- Count errors and warnings per diagnostic, not per record.
- Warning-only rows count as accepted under the documented default contract.

## Dependencies and scope

- **Related requirements:** [FR-025](FR-025.md), [FR-027](FR-027.md), [FR-028](FR-028.md), [FR-029](FR-029.md), [FR-036](FR-036.md).
- **Boundary:** Elapsed-time metrics and instrumentation are not implied by this requirement.

## Open design decisions

Define partial/fatal import summary flags and exact counters exported in JSON.

## Acceptance scenarios

### FR-030-SC01 — Summarize processed and rejected rows

**Given** a completed import contains accepted records and rejected records with one or more errors,  
**When** the result summary is calculated,  
**Then** Processed equals Accepted plus Rejected, with error and warning counts reflecting individual diagnostics.

### FR-030-SC02 — Count warning-only records correctly

**Given** an otherwise valid record produces warnings but no errors,  
**When** the import summary is calculated,  
**Then** the record remains accepted and warnings do not increase Rejected.
