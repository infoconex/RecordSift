# FR-010 — Map input columns to .NET properties

**Requirement:** [FR-010](../../requirements/functional.md)  
**Tracking issue:** [#19](https://github.com/infoconex/RecordSift/issues/19)  
**Priority:** Must  
**Verification status:** Planned — PR #115 adds automated evidence for explicit string-property mapping and ambiguous destination rejection. Full typed-member support and conversion remain dependent on FR-011.

## Purpose

Business-oriented source headers rarely match property names exactly.

## Functional requirement

**RecordSift shall:** Map declared source fields to destination .NET model members.

## Inputs and outputs

- **Inputs:** Source-to-member binding declarations and the destination model.
- **Outputs:** Values assigned to intended typed properties, or actionable mapping errors.

## Functional rules

- Allow explicit mapping even when source and property names differ.
- Reject ambiguous member mappings instead of selecting a source arbitrarily.
- Retain the original source field for conversion and validation diagnostics.

## Dependencies and scope

- **Related requirements:** [FR-009](FR-009.md), [FR-011](FR-011.md), [FR-013](FR-013.md), [FR-026](FR-026.md).
- **Boundary:** Column aliases and custom converters are separate capabilities (FR-014/FR-016).

## Initial implementation boundary

[ADR 0023](../../engineering/decisions/0023-explicit-string-property-mapping.md) introduces an initial, format-independent binding contract with ordinal, exact-case source-column and destination-property names. Its Application implementation assigns only to public writable `string` instance properties on types with a public parameterless constructor. Missing required source bindings are rejected; missing optional source values leave properties unset. Generalized non-string type conversion and immutable destination models remain separate decisions under FR-011 and FR-026.

## Open design decisions

Decide which writable member types and naming comparisons are supported.

## Acceptance scenarios

### FR-010-SC01 — Map differently named source columns

**Given** a schema maps CSV column 'Customer Id' to the CustomerId property,  
**When** a record is imported,  
**Then** the matching typed object receives the source value at CustomerId.

### FR-010-SC02 — Reject ambiguous property mapping

**Given** a schema maps multiple conflicting columns to the same destination without an explicit resolution,  
**When** schema mapping is configured,  
**Then** the ambiguity produces an actionable configuration failure.
