# FR-025 — Configurable validation severity (deferred)

**Requirement:** [FR-025](../../requirements/functional.md)  
**Tracking issue:** [#26](https://github.com/infoconex/RecordSift/issues/26)  
**Priority:** Future — not part of release 0.1  
**Verification status:** Planned — neither this feature nor executable tests are implemented.

## Purpose

Severity levels beyond a simple success/error classification may become useful later, but they are not necessary to establish a reliable initial import and validation contract.

## Functional requirement

**RecordSift shall:** for release 0.1, classify every processed data record as either accepted or rejected due to one or more errors; configurable non-error severity is deferred for separate future design approval.

## Inputs and outputs

- **Inputs:** For release 0.1, a schema and error-level validation rules; future severity configuration remains unspecified.
- **Outputs:** For release 0.1, accepted/rejected row counts and error diagnostics only; no warning-level outputs.

## Functional rules

- Release 0.1 does not emit warnings, warning-row counts, or a `severity` field in [JSON contract 1.0](../../specifications/import-result.md).
- An optional field is accepted when missing unless an independently specified requirement defines an error condition; it does not cause an advisory diagnostic by default.
- Rows with one or more validation errors are rejected once and retain all individual error diagnostics.
- A future extension to configurable severity must use a separately reviewed requirement update and, if JSON output changes incompatibly, a new JSON contract version.

## Dependencies and scope

- **Related requirements:** [FR-012](FR-012.md), [FR-017](FR-017.md), [FR-022](FR-022.md), [FR-030](FR-030.md), [FR-035](FR-035.md).
- **Boundary:** Future-only design placeholder; no warning behavior is required, tested, or promised for release 0.1.

## Open design decisions

Whether warnings or additional severities are worthwhile remains undecided. Do not add optional-field warning examples or elaborate severity policy to the initial implementation.

## Acceptance scenarios

### FR-025-SC01 — Future severity configuration remains out of scope

**Given** release 0.1 has an accepted-or-rejected outcome model,  
**When** the import result is produced,  
**Then** it has no configurable warning severity or warning-row counters.

### FR-025-SC02 — Future extensions must preserve the published initial contract

**Given** severity configurability is considered for a later release,  
**When** a contract change is proposed,  
**Then** the new behavior requires separate specification, scenario review, and appropriate versioned compatibility tests.

**Retired planned ID:** `FR-025-SC03` proposed an optional-field warning example but was withdrawn before implementation when the release 0.1 contract was simplified. Do not reuse the identifier.

## Verification notes

These scenarios are **not** release 0.1 implementation gates. The applicable binary outcome scenarios are covered by [FR-030](FR-030.md), [FR-028](FR-028.md), and [FR-035](FR-035.md); only a future design decision should authorize tests for configurable severity.
