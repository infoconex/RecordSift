# FR-027 — Return successfully validated records

**Requirement:** [FR-027](../../requirements/functional.md)  
**Tracking issue:** [#28](https://github.com/infoconex/RecordSift/issues/28)  
**Priority:** Must  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Consumers must be able to consume valid records even when a batch includes invalid rows.

## Functional requirement

**RecordSift shall:** Return accepted typed records separately from invalid-record diagnostics.

## Inputs and outputs

- **Inputs:** Results of parsing, conversion and validation.
- **Outputs:** Only accepted records, preserving source order, alongside independent diagnostic data.

## Functional rules

- Exclude rows with error-level validation failures from the accepted collection.
- Retain accepted rows in the same order they appeared in the input.
- Do not discard valid rows because another row is invalid in continue-on-error mode.
- Optional fields missing values do not automatically reject otherwise valid records; release 0.1 defines no warning status.

## Dependencies and scope

- **Related requirements:** [FR-025](FR-025.md), [FR-026](FR-026.md), [FR-028](FR-028.md), [FR-029](FR-029.md), [FR-030](FR-030.md).
- **Boundary:** Persistence to a database or returning partial invalid objects as accepted is outside scope.

## Open design decisions

Determine how accepted-record buffering and resource limits interact in large imports.

## Acceptance scenarios

### FR-027-SC01 — Return only valid records in source order

**Given** an input contains valid rows interspersed with invalid rows,  
**When** import completes in continue-on-error mode,  
**Then** accepted records are returned in original order and rejected rows are excluded.

### FR-027-SC02 — Return empty accepted collection for entirely invalid source

**Given** every input row fails one or more required validation rules,  
**When** import completes,  
**Then** no invalid record appears in the accepted results while diagnostics remain available.
