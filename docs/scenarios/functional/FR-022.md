# FR-022 — Support custom validation rules

**Requirement:** [FR-022](../../requirements/functional.md)  
**Tracking issue:** [#23](https://github.com/infoconex/RecordSift/issues/23)  
**Priority:** Must  
**Verification status:** Planned — legacy specification-planning metadata **only**, not current execution status. All 2 FR-022 acceptance scenarios are Automated with observed Windows CI evidence in [scenario-to-test traceability](../../testing/traceability.md).

## Purpose

Consumers must validate domain-specific business rules without modifying RecordSift's core.

## Functional requirement

**RecordSift shall:** Allow application-supplied validation rules to add standard diagnostics to imported records.

## Inputs and outputs

- **Inputs:** A typed record, custom rule and source/field context.
- **Outputs:** A list of structured validation diagnostics, or an accepted record when the rule passes.

## Functional rules

- Apply registered rules as part of the common validation pipeline.
- Preserve location, code and message information supplied by custom rule results.
- Keep rule failures separate from import infrastructure failures.
- Honor the established continue-on-error semantics for record validation.

## Dependencies and scope

- **Related requirements:** [FR-026](FR-026.md), [FR-028](FR-028.md), [FR-029](FR-029.md).
- **Boundary:** Arbitrary expression interpretation, user-supplied scripts and remote validation are not part of this requirement.

## Open design decisions

Resolved by [ADR 0029](../../engineering/decisions/0029-domain-custom-record-validation.md). After required-value, length, conversion and range validation, run custom rules in registration order before duplicate-identifier tracking. Each invalid rule emits one registered, sanitized `VALIDATION_FAILED` diagnostic with a field identifier or null for the whole record. Rule exceptions are caller programming failures and are not mislabeled as conversion failures. Rules have no implicit access to prior records.

## Acceptance scenarios

### FR-022-SC01 — Integrate custom validation failures

**Given** a registered validator reports a record-specific failure,  
**When** validation executes,  
**Then** the standard diagnostic result includes that failure with its field/record context.

### FR-022-SC02 — Accept a passing custom validator

**Given** a registered validator returns no violations,  
**When** a valid record is processed,  
**Then** the validator does not cause a rejection.
