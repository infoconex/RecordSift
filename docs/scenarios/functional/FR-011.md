# FR-011 — Convert common .NET data types

**Requirement:** [FR-011](../../requirements/functional.md)  
**Tracking issue:** [#4](https://github.com/infoconex/RecordSift/issues/4)  
**Priority:** Must  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Importers should interpret common business field types consistently rather than leaving every consumer to parse strings.

## Functional requirement

**RecordSift shall:** Convert declared source values to common .NET field types under explicit parsing rules.

## Inputs and outputs

- **Inputs:** Source field values, schema-declared .NET type, null policy and culture.
- **Outputs:** Converted string, integer, decimal, date, boolean and nullable values; conversion diagnostics for invalid values.

## Functional rules

- Support the documented initial primitive and nullable types.
- Use explicitly configured culture for culture-sensitive values.
- Do not silently coerce malformed values into defaults.
- Keep null/empty handling consistent with required/optional field rules.

## Dependencies and scope

- **Related requirements:** [FR-009](FR-009.md), [FR-012](FR-012.md), [FR-018](FR-018.md), [NFR-005](../non-functional/NFR-005.md).
- **Boundary:** Custom application-specific converters are handled separately in FR-016.

## Open design decisions

Choose initial date formats, boolean tokens, numeric overflow behavior and rounding policy.

## Acceptance scenarios

### FR-011-SC01 — Convert supported primitive types

**Given** source fields contain valid strings, integers, decimals, dates, booleans, and nullable values,  
**When** the fields are converted with explicit parsing settings,  
**Then** the typed record has correct values and null semantics.

### FR-011-SC02 — Respect configured culture

**Given** a numeric/date value uses a non-default culture format,  
**When** conversion is performed with that explicitly configured culture,  
**Then** the value is interpreted according to the selected culture rather than machine locale.
