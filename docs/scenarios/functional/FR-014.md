# FR-014 — Support column name aliases

**Requirement:** [FR-014](../../requirements/functional.md)  
**Tracking issue:** [#16](https://github.com/infoconex/RecordSift/issues/16)  
**Priority:** Should  
**Verification status:** Automated — both scenarios accepted; [post-merge Windows #41218864891](https://github.com/infoconex/RecordSift/actions/runs/41218864891) passed. See [scenario-to-test traceability](../../testing/traceability.md).

## Purpose

Feeds may provide several accepted names for the same logical field.

## Functional requirement

**RecordSift shall:** Allow a schema field to declare one or more alternative source column names.

## Inputs and outputs

- **Inputs:** A canonical field definition and optional alternate headers.
- **Outputs:** The canonical field binding when exactly one accepted name matches; a diagnostic for collisions.

## Functional rules

- Recognize configured aliases during header-based binding.
- Do not silently choose between simultaneously present conflicting aliases.
- Keep source name and logical target field identifiable in error reporting.

## Dependencies and scope

- **Related requirements:** [FR-004](FR-004.md), [FR-009](FR-009.md), [FR-010](FR-010.md).
- **Boundary:** Should feature; normalization beyond configured aliases is not promised.

## Open design decisions

The alias precedence, casing and collision questions are resolved for release 0.1 as follows:

- A canonical heading and each explicitly configured alias are equally valid, matched with ordinal case-sensitive comparison; no whitespace trimming, culture-sensitive folding, or implicit normalization occurs.
- Exactly one matching source heading is required for each present logical field. Canonical plus alias, multiple aliases, or duplicate occurrences of a matching heading return the existing `AMBIGUOUS_COLUMN` source diagnostic. This applies even if record values are equal: ambiguity is decided before data rows are read.
- A schema rejects colliding canonical names and aliases across declarations at configuration time; alias collections are copied into an immutable snapshot.
- Successful bindings retain the canonical source-field name and actual physical source index, allowing callers to correlate the original header with the logical property mapping. Ambiguity diagnostics identify the canonical field, without embedding untrusted source values.
- Headerless positional binding and previously declared required-value, length, type conversion and culture rules are unaffected.

## Acceptance scenarios

### FR-014-SC01 — Resolve a configured alias

**Given** a schema defines 'Client Number' as an alias for CustomerId,  
**When** a source uses the alias heading,  
**Then** the correct property is populated.

### FR-014-SC02 — Reject conflicting aliases

**Given** two source columns match different aliases for the same destination with incompatible values,  
**When** schema binding occurs,  
**Then** an ambiguous mapping is identified rather than selecting silently.
