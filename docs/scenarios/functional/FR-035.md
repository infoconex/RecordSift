# FR-035 — Export validation results as JSON

**Requirement:** [FR-035](../../requirements/functional.md)  
**Tracking issue:** [#36](https://github.com/infoconex/RecordSift/issues/36)  
**Priority:** Must  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Automated import pipelines need machine-readable reports that can be archived or processed by other tools.

## Functional requirement

**RecordSift shall:** Serialize a completed import result and its validation diagnostics to a stable JSON representation.

## Inputs and outputs

- **Inputs:** An existing in-memory import result and report configuration.
- **Outputs:** A JSON document with standard summary fields and structured diagnostics.

## Functional rules

- Serialize from an existing result without re-importing its source.
- Preserve diagnostic identity and documented ordering.
- Do not include raw sensitive values or absolute source paths by default.
- Treat serializer behavior and property naming as part of the versioned report contract.

## Dependencies and scope

- **Related requirements:** [FR-028](FR-028.md), [FR-030](FR-030.md), [FR-036](FR-036.md), [NFR-008](../non-functional/NFR-008.md), [NFR-010](../non-functional/NFR-010.md).
- **Boundary:** Writing CSV, Excel or a database report is outside this requirement.

## Open design decisions

Choose the JSON schema, field casing, date conventions and compatibility/versioning strategy.

## Acceptance scenarios

### FR-035-SC01 — Serialize a completed validation report

**Given** a completed result includes counts and diagnostics,  
**When** JSON reporting is invoked,  
**Then** a JSON document contains stable expected fields, values, and diagnostic order.

### FR-035-SC02 — Generate reports without re-reading source

**Given** the original input is no longer available but a completed result object exists,  
**When** a report is generated,  
**Then** serialization succeeds using only the in-memory result.

### FR-035-SC03 — Avoid sensitive source values

**Given** input contains sensitive field data that appears in invalid records,  
**When** JSON diagnostics are serialized with default settings,  
**Then** raw source values and absolute file paths are not emitted.
