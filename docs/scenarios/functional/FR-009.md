# FR-009 — Define expected columns in a schema

**Requirement:** [FR-009](../../requirements/functional.md)  
**Tracking issue:** [#15](https://github.com/infoconex/RecordSift/issues/15)  
**Priority:** Must  
**Verification status:** Planned — this specification defines the scenarios; automated execution status and evidence are maintained separately in the traceability matrix.

## Purpose

Shared schema definitions prevent accidental mapping and validation of the wrong source columns.

## Functional requirement

**RecordSift shall:** Allow explicit declaration of expected columns in an import schema.

## Inputs and outputs

- **Inputs:** Field definitions, expected names/positions, and requiredness metadata.
- **Outputs:** Validated source-column bindings or clear missing/ambiguous-column diagnostics.

## Functional rules

- Validate schema bindings before accepting data as correctly mapped.
- Report absent required source columns separately from missing values in individual records.
- Use the same logical schema semantics across CSV and XLSX readers.

## Dependencies and scope

- **Related requirements:** [FR-004](FR-004.md), [FR-005](FR-005.md), [FR-010](FR-010.md), [FR-012](FR-012.md), [FR-013](FR-013.md).
- **Boundary:** Conversion, default values and aliases have their own requirements.

## Open design decisions

Resolved for the minimal schema binder by [ADR 0003](../../engineering/decisions/0003-source-column-binding.md): ordinal case-sensitive matching; duplicate declarations are configuration errors; duplicate matched source headers are ambiguous; additional undeclared headers are ignored. Revisit explicitly if reader integration requires additional modes.

## Acceptance scenarios

### FR-009-SC01 — Declare required source columns

**Given** a schema declares expected columns and the source contains them,  
**When** schema binding begins,  
**Then** all declared source columns are correctly recognized.

### FR-009-SC02 — Reject missing required columns

**Given** a source lacks a schema-required column,  
**When** schema binding begins,  
**Then** a clear missing-column diagnostic is reported before records are silently misinterpreted.
