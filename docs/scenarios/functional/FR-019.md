# FR-019 — Validate field length constraints

**Requirement:** [FR-019](../../requirements/functional.md)  
**Tracking issue:** [#17](https://github.com/infoconex/RecordSift/issues/17)  
**Priority:** Must  
**Verification status:** Planned — legacy specification-planning metadata **only**, not current execution status. Both FR-019 acceptance scenarios are Automated with observed Windows CI evidence in [scenario-to-test traceability](../../testing/traceability.md).

## Purpose

Business schemas often impose maximum field lengths that need enforcement before accepting imported records.

## Functional requirement

**RecordSift shall:** Allow validation of configured minimum/maximum field lengths as supported by the rule contract.

## Inputs and outputs

- **Inputs:** A string field value and declared length constraint.
- **Outputs:** A field-specific length diagnostic or successful boundary validation.

## Functional rules

- Reject values exceeding the configured maximum.
- Accept values exactly at an inclusive maximum.
- Report the field and logical record where the violation occurred.
- Apply the same definition of length across supported import formats.

## Dependencies and scope

- **Related requirements:** [FR-009](FR-009.md), [FR-028](FR-028.md).
- **Boundary:** Byte-length limits for file decoding and global resource limits are separate quality concerns.

## Open design decisions

Resolved by [ADR 0026](../../engineering/decisions/0026-domain-field-length-validation.md): the explicitly configured inclusive minimum/maximum use untrimmed UTF-16 code-unit length (`string.Length`) of the present decoded source value. Bounds are not inferred; missing optional columns remain optional. No automatic normalization or trimming.

## Acceptance scenarios

### FR-019-SC01 — Reject values exceeding maximum length

**Given** a field exceeds its configured maximum length,  
**When** the field is validated,  
**Then** a length diagnostic identifies the failing field and record.

### FR-019-SC02 — Accept exactly the maximum length

**Given** a string is exactly the configured permitted length,  
**When** the field is validated,  
**Then** no maximum-length violation is raised.
