# FR-038 — Export validation errors as CSV

**Requirement:** [FR-038](../../requirements/functional.md)  
**Tracking issue:** [#39](https://github.com/infoconex/RecordSift/issues/39)  
**Priority:** Should  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Some integrations need a portable list of rejected fields for operational review.

## Functional requirement

**RecordSift shall:** Export existing validation diagnostics into a CSV report with stable field headings.

## Inputs and outputs

- **Inputs:** An existing import result and CSV reporting options.
- **Outputs:** A CSV text report containing escaped structured diagnostic rows.

## Functional rules

- Use correct quoting for commas, quotes and newlines in diagnostic messages.
- Do not re-read the original input.
- Keep source/record/field columns consistent with the structured result.
- Do not emit raw sensitive input values by default.

## Dependencies and scope

- **Related requirements:** [FR-028](FR-028.md), [FR-036](FR-036.md), [FR-037](FR-037.md).
- **Boundary:** Should scope; no direct file upload, external service delivery or Excel formatting.

## Open design decisions

Define empty-report behavior, column ordering, encoding and delimiter configuration.

## Acceptance scenarios

### FR-038-SC01 — Export escaped diagnostics

**Given** an import result contains errors with commas, quotes, or newlines in human-readable messages,  
**When** diagnostics are exported to CSV,  
**Then** stable headers and correctly escaped rows allow another CSV reader to reconstruct the messages.

### FR-038-SC02 — Export an error-free result

**Given** an import produces no diagnostics,  
**When** error-only CSV export is requested,  
**Then** output follows the documented empty-export policy and contains no invented errors.
