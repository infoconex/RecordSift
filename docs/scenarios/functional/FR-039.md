# FR-039 — Provide custom report formatting

**Requirement:** [FR-039](../../requirements/functional.md)  
**Tracking issue:** [#40](https://github.com/infoconex/RecordSift/issues/40)  
**Priority:** Future  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Applications may need specialized reports without changing RecordSift's parsing and validation internals.

## Functional requirement

**RecordSift shall:** Expose a configurable report-formatting extension that consumes completed import results.

## Inputs and outputs

- **Inputs:** An existing import result and registered report formatter.
- **Outputs:** Application-specific report output or a clearly classified formatter failure.

## Functional rules

- Pass the completed result to the formatter without re-importing data.
- Keep formatter failure separate from import processing success/failure.
- Respect privacy defaults unless the caller explicitly opts into exposing additional data.
- Preserve the core result even when report generation fails.

## Dependencies and scope

- **Related requirements:** [FR-035](FR-035.md), [FR-036](FR-036.md), [FR-038](FR-038.md).
- **Boundary:** Future scope; this does not imply executing arbitrary scripts or plugins from untrusted files.

## Open design decisions

Define the extension contract, error policy and output target ownership.

## Acceptance scenarios

### FR-039-SC01 — Invoke a registered report formatter

**Given** a custom formatter is registered and a completed result exists,  
**When** report output is requested,  
**Then** the formatter receives the existing result and produces the configured format without re-importing.

### FR-039-SC02 — Handle formatter failure

**Given** a custom formatter reports a formatting problem,  
**When** report output is requested,  
**Then** the reporting failure is surfaced clearly without losing the original import result.
