# FR-003 — Configure CSV delimiters

**Requirement:** [FR-003](../../requirements/functional.md)  
**Tracking issue:** [#10](https://github.com/infoconex/RecordSift/issues/10)  
**Priority:** Must  
**Verification status:** Planned for end-to-end typed import acceptance. Raw reader/table component tests are implemented and observed in [Windows #41081248991](https://github.com/infoconex/RecordSift/actions/runs/41081248991) (112/112 NUnit).

## Purpose

Delimited integrations use semicolons, tabs or other characters, not always commas.

## Functional requirement

**RecordSift shall:** Permit callers to configure the field delimiter used by CSV parsing.

## Inputs and outputs

- **Inputs:** CSV input and an explicit delimiter configuration.
- **Outputs:** Field boundaries based on the chosen delimiter, or a configuration/parse failure.

## Functional rules

- Apply the selected delimiter consistently across the source.
- Preserve delimiters inside correctly quoted field values.
- Reject unsupported or ambiguous delimiter settings with clear configuration errors.
- Keep delimiter settings independent of numeric and date culture.

## Dependencies and scope

- **Related requirements:** [FR-001](FR-001.md), [FR-004](FR-004.md), [FR-006](FR-006.md).
- **Boundary:** Quote escaping, header policy and decoding are separately specified.

## Open design decisions

No unresolved delimiter-setting design decision blocks release 0.1. [ADR 0009](../../engineering/decisions/0009-configurable-csv-delimiters.md) specifies the supported single-character delimiter set and safe validation. Future delimiter auto-detection or multi-character formats would require separately approved requirements and characterization tests.

## Delimiter policy (ADR 0009)

The [approved delimiter decision](../../engineering/decisions/0009-configurable-csv-delimiters.md) supports one non-control, non-whitespace character (except tab, which is supported), excluding double quotes and UTF-16 surrogate code units. Default is comma. Empty, null, multi-character, space, newline, and quote settings are invalid. Unsupported settings cause the stable, source-scoped `INVALID_CSV_DELIMITER` diagnostic without reading the input. Delimiter auto-detection is deferred.

## Acceptance scenarios

### FR-003-SC01 — Use a semicolon delimiter

**Given** a semicolon-delimited CSV fixture includes a quoted semicolon,  
**When** the importer is configured with ';' as delimiter,  
**Then** columns parse correctly and the quoted semicolon stays inside its value.

### FR-003-SC02 — Reject an invalid delimiter configuration

**Given** the delimiter setting is unsupported or ambiguous,  
**When** import configuration is validated,  
**Then** the setting is rejected with a clear configuration diagnostic before importing.
