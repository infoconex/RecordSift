# RecordSift 0.1 — security assessment and remediation register

**Review started:** 2026-10-31. **Technical reassessment completed:** 2026-10-31. **Release target:** Windows, .NET Framework 4.8, C# 7.3. **Original review baseline:** `release/0.1` at `0d381cdedd882cef5d36ddeabb4f7569f0358ea3`. **Verified post-remediation source checkpoint:** `76fb60886b0dcd0d81c3e2a1818e086c7b38cd97`. **Security recommendation:** **CONDITIONAL GO** for the assessed technical scope, **NO-GO for source promotion until explicit sole-maintainer owner GO**; publication separately unauthorized. This report is a source-level security review and targeted regression plan, **not penetration-test or fuzz-test certification**.

**Governance:** issue [#199](https://github.com/infoconex/RecordSift/issues/199) remains open. Draft main promotion [#209](https://github.com/infoconex/RecordSift/pull/209) must not be merged. A security remediation changes the integration Git tree, so the previously reviewed promotion PR/head and green jobs cannot certify the new candidate. Do not retarget or update it silently; replace/update the promotion candidate only under fresh owner review. No main/tag/GitHub Release/NuGet publication is authorized.

## Assessment coverage and open verification questions

- **CSV:** malformed and multiline CSV, custom delimiter, decoded-character budget and strict decoding have existing acceptance paths. Additional adversarial row/field-count memory profiling remains an evidence gap, not a proved bypass.
- **XLSX:** malformed packages, expansion guard, macro-part rejection, formula cached-value behavior, row/column/cell limits, workbook and worksheet selection have existing tests. Actual ZIP byte counting is merged under #210/#211; #212 separately addresses ExcelDataReader 3.9.0 shared-string preallocation from untrusted `uniqueCount`. Issue #218 / PR #219 addresses the separate source-supported `.bin` relationship path to vendor BIFF record-length allocation; this is a guarded input-format boundary, not a blanket ban on unrelated binary ZIP attachments. Its test-only RED run confirmed acceptance of a harmless hybrid input and final verification must include four green PR and postmerge jobs. A secure `XmlReader` preflight explicitly prohibits DTDs and external resolution for shared-string inspection; this does **not** certify every downstream vendor XML parser or worst-case heap size. An OpenXML part is data, not automatically executable; no Excel/COM automation is used.
- **Validation:** shared pipeline, mapping-conversion errors, duplicate state, bounded regex, cancellation and fail-fast have dedicated tests. Mapper/callback code remains caller-owned.
- **Reporting:** JSON uses DataContractJsonSerializer for a fixed projection of registered diagnostics and excludes accepted records. CSV is not spreadsheet-safe by design. Arbitrary opaque metadata can include control characters or sensitive content; downstream logs/renderers must handle it contextually.
- **Dependencies/CI:** eleven pinned runtime packages; three Windows Actions workflows with four required check contexts. All four [PR #211](https://github.com/infoconex/RecordSift/pull/211) checks and all four exact post-squash integration checks succeeded, including NUnit/API/advisory audit, independent prerelease+stable consumers and documentation. Repeat after #212 merges.
- **Unverified:** independent penetration/fuzz testing, actual worst-case heap size under crafted shared strings, complete secret scanning, runtime behavior of every malformed-XML variant, and exhaustive third-party code audits.

## Remediation acceptance and release recommendation

For [#210](https://github.com/infoconex/RecordSift/issues/210), require green Windows NUnit (at least the original 387 tests plus new tests), compiled API gate (425 entries), dependency advisory audit, independently installed RC/stable package consumer, and docs validation on the issue PR **and its actual post-squash release integration SHA**. No public-API or serialized-output changes are planned.

**Technical security recommendation: CONDITIONAL GO for Windows/net48 release 0.1 after fixes #210 and #212**, with no demonstrated unresolved High/Critical exploit in the assessed scope. The tested final source checkpoint passed **392 NUnit tests, the unchanged 425-entry public API gate, 7 JSON fixtures, pinned dependency/advisory audit, independent prerelease/stable package consumers, and docs checks**. The library is **not certified fully secure**: malicious-input fuzzing, worst-case eager parser memory, independent pentesting and complete secret scanning were not performed; existing low-risk CSV/reporting/cancellation limitations remain. The sole maintainer must explicitly evaluate/accept remaining risks, conduct the second-pass review, and record a new GO against the actual final promotion candidate under [issue #199](https://github.com/infoconex/RecordSift/issues/199). **No owner GO has been recorded, so promotion to main and public distribution remain NO-GO.** The pre-security draft [PR #209](https://github.com/infoconex/RecordSift/pull/209) remains a fixed, unmerged, superseded 13-file candidate. A separate decision authorizes any future tag, GitHub Release or NuGet publication.
