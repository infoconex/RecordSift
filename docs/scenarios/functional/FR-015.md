# FR-015 — Support default field values

**Requirement:** [FR-015](../../requirements/functional.md)  
**Tracking issue:** [#20](https://github.com/infoconex/RecordSift/issues/20)  
**Priority:** Should  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Imports sometimes omit optional fields for which a business-defined default is appropriate.

## Functional requirement

**RecordSift shall:** Allow a schema to supply a default value for a field that is absent under a defined policy.

## Inputs and outputs

- **Inputs:** A field default, source field/value presence and destination type.
- **Outputs:** The configured default where applicable; otherwise the existing source value.

## Functional rules

- Use a default only when the documented missing-value condition applies.
- Never overwrite a valid present value simply because a default exists.
- Validate that defaults are compatible with the declared field type.
- Distinguish default application from required-field errors.

## Dependencies and scope

- **Related requirements:** [FR-011](FR-011.md), [FR-012](FR-012.md), [FR-017](FR-017.md).
- **Boundary:** Should feature; no implicit universal default values.

## Open design decisions

Decide whether empty values count as missing and when defaults are converted/validated.

## Acceptance scenarios

### FR-015-SC01 — Apply a configured default

**Given** an optional field is absent and has a schema default,  
**When** import occurs,  
**Then** the resulting record receives the declared default.

### FR-015-SC02 — Do not overwrite present data

**Given** a field has a default but the source contains a valid value,  
**When** import occurs,  
**Then** the source value takes precedence over the default.
