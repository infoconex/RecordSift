# FR-013 — Map columns by name or position

**Requirement:** [FR-013](../../requirements/functional.md)  
**Tracking issue:** [#12](https://github.com/infoconex/RecordSift/issues/12)  
**Priority:** Must  
**Verification status:** Planned — unit-level positional-binding contract is tested; integration with real imports and typed values remains unverified.

## Purpose

Some files map fields by column name and others by ordinal position.

## Functional requirement

**RecordSift shall:** Support explicit source column binding by name or zero/one-based position as defined by the API.

## Inputs and outputs

- **Inputs:** Column binding declarations and source header or field order.
- **Outputs:** Unambiguous mapping of source fields or a clear invalid-binding diagnostic.

## Functional rules

- Apply positional bindings predictably in headerless sources.
- Apply named bindings using the configured header-matching policy.
- Reject invalid positions and ambiguous binding definitions.
- Retain original source-column information for diagnostics.

## Dependencies and scope

- **Related requirements:** [FR-004](FR-004.md), [FR-009](FR-009.md), [FR-010](FR-010.md).
- **Boundary:** Aliases and automatic positional inference are not assumed.

## Open design decisions

Settled by [ADR 0004](../../engineering/decisions/0004-positional-column-binding.md): zero-based indexing (consistent with FR-009); named and positional modes are separate explicit binding operations, without mixed inference.

## Acceptance scenarios

### FR-013-SC01 — Use named and positional bindings

**Given** fixtures include a headed source and a headerless source,  
**When** their schema mappings use names and positions respectively,  
**Then** both bind fields correctly and produce equivalent typed values.

### FR-013-SC02 — Reject invalid positional binding

**Given** a mapping selects a column position beyond the available data,  
**When** records are imported,  
**Then** an actionable binding or record diagnostic is produced rather than reading an unrelated value.

## Verification notes

Use the [TDD and testing strategy](../../testing/strategy.md). Connect each scenario to an actual test method and a CI run in [traceability](../../testing/traceability.md) when implemented. Unit-level tests demonstrate source field position resolution and classified binding errors for supplied field counts. Do not mark SC01 or SC02 fully verified until actual headed and headerless sources produce equivalent typed records and invalid positions fail safely during import.
