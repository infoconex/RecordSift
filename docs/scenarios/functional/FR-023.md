## Purpose

Basic field patterns are a common validation need distinct from full custom code.

## Functional requirement

**RecordSift shall:** Permit a field to declare a regular-expression validation rule.

## Inputs and outputs

- **Inputs:** A string field value, configured expression and validation options.
- **Outputs:** A pattern diagnostic when the field does not match or an accepted value when it does.

## Functional rules

- Evaluate patterns against decoded and converted field values as defined by the field contract.
- Return a field-specific failure for nonmatching input.
- Reject invalid pattern configuration rather than silently skipping validation.
- Apply a bounded or explicitly configurable pattern timeout to avoid pathological evaluation.

## Dependencies and scope

- **Related requirements:** [FR-017](FR-017.md), [FR-022](FR-022.md), [FR-028](FR-028.md), [NFR-007](../non-functional/NFR-007.md).
- **Boundary:** Should scope; no arbitrary script execution or unbounded user-defined regex by default.

## Open design decisions

The release 0.1 rule is a Domain-owned `FieldPatternRule` associated with an exact-case canonical schema column. Rules are optional and snapshotted when `ImportSchema` is constructed; null, duplicate or undeclared field rules fail configuration. An invalid or blank pattern fails configuration with a resource-backed sanitized argument error.

Patterns are evaluated against decoded, untrimmed source strings **before typed property conversion**, after existing required-value and length checks. An absent or null optional field is not made required; a present empty string is evaluated normally. A configured default applied to an absent optional column is evaluated as a present value. The .NET Framework regex engine uses `RegexOptions.CultureInvariant` with case-sensitive substring matching; callers include anchors when requiring a complete value match. No ambient culture normalization occurs.

Each pattern evaluation has an explicit finite timeout of 250 milliseconds by default; a caller may choose a timeout from 1 millisecond to 10 seconds. Infinite or nonpositive timeouts and excessive budgets are rejected. A nonmatch or regex timeout rejects only that logical record through the existing `VALIDATION_FAILED` field-scoped sanitized diagnostic. No original source text, pattern content or parser exception is included in messages. Pattern evaluation is synchronous and requires no vendor package, scripting, or service.

`FieldPatternRule` has a private, construction-time-validated regex instance and no mutable public setters. `ImportSchema` snapshots the ordered rule registrations into a read-only collection; later mutation of the caller's registration list does not alter validation. Regex matching does not update the schema or rule, so the same configured schema can be reused across independent imports (including concurrent callers). Caller-owned mapper and custom validator delegates may have separate thread-safety constraints. Validation follows the shared required → length → regex → typed conversion → range → custom → duplicate ordering, and stops at the first failing stage for each record.

## Acceptance scenarios

### FR-023-SC01 — Apply a configured expression

**Given** a field is restricted by a regular expression,  
**When** the input value fails to match,  
**Then** the record receives a field-level pattern diagnostic.

### FR-023-SC02 — Accept matching input

**Given** a field value matches the configured pattern,  
**When** the record is validated,  
**Then** the pattern rule does not report an error.
