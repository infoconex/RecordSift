# FR-010 — Map input columns to .NET properties

**Requirement:** [FR-010](../../requirements/functional.md)  
**Tracking issue:** [#19](https://github.com/infoconex/RecordSift/issues/19)  
**Priority:** Must  
**Verification status:** Planned — this is the authoritative scenario specification; observed automation status and CI evidence belong in the traceability matrix.

## Purpose

Business-oriented source headers rarely match property names exactly.

## Functional requirement

**RecordSift shall:** Map declared source fields to destination .NET model members.

## Inputs and outputs

- **Inputs:** Source-to-member binding declarations and the destination model.
- **Outputs:** Values assigned to intended typed properties, or actionable mapping errors.

## Functional rules

- Allow explicit mapping even when source and property names differ.
- Reject ambiguous member mappings instead of selecting a source arbitrarily.
- Retain the original source field for conversion and validation diagnostics.

## Dependencies and scope

- **Related requirements:** [FR-009](FR-009.md), [FR-011](FR-011.md), [FR-013](FR-013.md), [FR-026](FR-026.md).
- **Boundary:** Column aliases and custom converters are separate capabilities (FR-014/FR-016).

## Supported release 0.1 mapping contract

[ADR 0023](../../engineering/decisions/0023-explicit-string-property-mapping.md) defines reusable, ordinal exact-case source-column/property mappings. `PrimitivePropertyMapper<T>` supports public writable, non-indexed instance properties on reference types with public parameterless constructors: `string`, `int`, `decimal`, `DateTime`, `bool`, and the supported nullable value types. An explicit culture determines primitive conversions. `StringPropertyMapper<T>` remains a compatibility wrapper limited to string destinations.

Misconfigured, duplicated, incorrectly cased, missing, inaccessible, read-only, or unsupported destination properties fail before records are processed; no partial record is accepted. A missing required source binding fails schema validation; missing optional source fields leave their destinations unset. Per-record conversion errors preserve original source-column and row/line provenance without printing field values. Caller dictionaries do not change ordinal matching.

The Domain declarations are format-independent and available to future XLSX workflows. Their existence is not XLSX integration evidence. Required *cell values* are separately validated by FR-017; immutable model construction, nested members and custom converters are outside this release 0.1 FR-010 scope.

## Open design decisions

For the release 0.1 supported destination scope, property accessibility, type support, constructor policy and identifier comparison have been resolved by ADR 0023 and tested in PR #117. Whether future immutable or nested members require an extended contract remains a separate FR-026 design decision.

## Acceptance scenarios

### FR-010-SC01 — Map differently named source columns

**Given** a schema maps CSV column 'Customer Id' to the CustomerId property,  
**When** a record is imported,  
**Then** the matching typed object receives the source value at CustomerId.

### FR-010-SC02 — Reject ambiguous property mapping

**Given** a schema maps multiple conflicting columns to the same destination without an explicit resolution,  
**When** schema mapping is configured,  
**Then** the ambiguity produces an actionable configuration failure.
