# FR-006 — Configure CSV text encoding

**Requirement:** [FR-006](../../requirements/functional.md)  
**Tracking issue:** [#3](https://github.com/infoconex/RecordSift/issues/3)  
**Priority:** Must  
**Verification status:** Planned — legacy specification-planning metadata **only**, not current execution status. Both FR-006 acceptance scenarios are Automated with observed Windows CI evidence in [scenario-to-test traceability](../../testing/traceability.md).

## Purpose

Incorrect character decoding can corrupt values before validation.

## Functional requirement

**RecordSift shall:** Allow callers to configure the character encoding used for CSV input.

## Inputs and outputs

- **Inputs:** A byte source or stream, chosen encoding and decoding error policy.
- **Outputs:** Correctly decoded text or a classified source decoding failure.

## Functional rules

- Use the configured encoding instead of silently relying on the system code page.
- Preserve valid non-ASCII characters when mapping values.
- Support a clear error when strict decoding encounters invalid bytes.
- Distinguish character decoding from data-type conversion.

## Dependencies and scope

- **Related requirements:** [FR-001](FR-001.md), [NFR-004](../non-functional/NFR-004.md), [NFR-005](../non-functional/NFR-005.md).
- **Boundary:** Numeric/date culture and delimiter selection are separate settings.

## Open design decisions

Resolved by [ADR 0025](../../engineering/decisions/0025-configurable-csv-text-encoding.md): callers must supply an explicit runtime-supported encoding; UTF-8 and ISO-8859-1 form the initial verified baseline. Strict decoding is the default. Replacement decoding requires explicit opt-in. Byte decoding belongs to Infrastructure; existing TextReader import behavior remains unchanged.

## Acceptance scenarios

### FR-006-SC01 — Decode a configured legacy encoding

**Given** a CSV fixture is encoded using an explicitly supported non-UTF-8 encoding,  
**When** the corresponding encoding is configured,  
**Then** non-ASCII characters are decoded and imported correctly.

### FR-006-SC02 — Detect invalid bytes according to policy

**Given** CSV bytes are invalid for a configured strict decoder,  
**When** import is attempted,  
**Then** an actionable source decoding failure is reported instead of silently corrupting data.
