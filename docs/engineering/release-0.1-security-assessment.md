# RecordSift 0.1 — security assessment and remediation register

**Review started:** 2026-10-31. **Release target:** Windows, .NET Framework 4.8, C# 7.3. **Review baseline:** `release/0.1` at `0d381cdedd882cef5d36ddeabb4f7569f0358ea3`. **Decision:** **HOLD** during assessment/remediation and until sole-maintainer second-pass owner GO. This report is a source-level security review and targeted regression plan, **not penetration-test or fuzz-test certification**.

**Governance:** issue [#199](https://github.com/infoconex/RecordSift/issues/199) remains open. Draft main promotion [#209](https://github.com/infoconex/RecordSift/pull/209) must not be merged. A security remediation changes the integration Git tree, so the previously reviewed promotion PR/head and green jobs cannot certify the new candidate. Do not retarget or update it silently; replace/update the promotion candidate only under fresh owner review. No main/tag/GitHub Release/NuGet publication is authorized.

## Assessment coverage and open verification questions

- **CSV:** malformed and multiline CSV, custom delimiter, decoded-character budget and strict decoding have existing acceptance paths. Additional adversarial row/field-count memory profiling remains an evidence gap, not a proved bypass.
- **XLSX:** malformed packages, expansion guard, macro-part rejection, formula cached-value behavior, row/column/cell limits, workbook and worksheet selection have existing tests. Actual ZIP byte counting is merged under #210/#211; #212 separately addresses ExcelDataReader 3.9.0 shared-string preallocation from untrusted `uniqueCount`. A secure `XmlReader` preflight explicitly prohibits DTDs and external resolution for shared-string inspection; this does **not** certify every downstream vendor XML parser or worst-case heap size. An OpenXML part is data, not automatically executable; no Excel/COM automation is used.
- **Validation:** shared pipeline, mapping-conversion errors, duplicate state, bounded regex, cancellation and fail-fast have dedicated tests. Mapper/callback code remains caller-owned.
- **Reporting:** JSON uses DataContractJsonSerializer for a fixed projection of registered diagnostics and excludes accepted records. CSV is not spreadsheet-safe by design. Arbitrary opaque metadata can include control characters or sensitive content; downstream logs/renderers must handle it contextually.
- **Dependencies/CI:** eleven pinned runtime packages; three Windows Actions workflows with four required check contexts. All four [PR #211](https://github.com/infoconex/RecordSift/pull/211) checks and all four exact post-squash integration checks succeeded, including NUnit/API/advisory audit, independent prerelease+stable consumers and documentation. Repeat after #212 merges.
- **Unverified:** independent penetration/fuzz testing, actual worst-case heap size under crafted shared strings, complete secret scanning, runtime behavior of every malformed-XML variant, and exhaustive third-party code audits.
