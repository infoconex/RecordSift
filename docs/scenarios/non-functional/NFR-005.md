# NFR-005 — Make culture-sensitive parsing configurable

**Requirement:** [NFR-005](../../requirements/non-functional.md)  
**Tracking issue:** [#45](https://github.com/infoconex/RecordSift/issues/45)  
**Priority:** Must — release 0.1 quality requirement (later-platform scenarios remain future milestones).  
**Verification status:** Planned — no executable checks have run.

## NFR-005-SC01 — Parse in an explicit non-default culture

**Given** a source contains locale-specific decimal and date strings,  
**When** a matching culture is configured,  
**Then** numeric and date values are interpreted according to that explicit culture.

## NFR-005-SC02 — Do not silently use ambient culture

**Given** identical input/settings are processed under different process cultures,  
**When** imports complete,  
**Then** equivalent typed values and validation results are returned.

## Verification notes

**Observed evidence:** [Windows PR #41186263320](https://github.com/infoconex/RecordSift/actions/runs/41186263320) passed 292/292 NUnit tests (107 Domain, 48 Application, 100 CSV, 19 Reporting, 18 XLSX), including all six NFR-005 acceptance tests with a real local XLSX culture fixture. [Documentation PR #41186263310](https://github.com/infoconex/RecordSift/actions/runs/41186263310) passed. Both scenarios are Automated in traceability; the specification planning label is retained by validation policy.

Acceptance combines Domain-only tests of explicit `en-US`, `fr-FR`, and `de-DE` parsing with real CSV and XLSX integration tests. A compact local OpenXML fixture contains French-format numeric and date **text** cells (not Excel-native formatted numeric/date cells), so the shared RecordSift conversion path is exercised. Tests cover grouping and decimal separators, dates, nullable blanks, Boolean's nonlocalized `true`/`false` semantics, unsupported targets, invalid values, decimal precision loss, and a defensive clone of caller-supplied mutable `CultureInfo`. Each integration test compares typed values, result summaries, and source diagnostics across changing ambient process and UI cultures; tests restore both in `finally`. Native XLSX numeric and DateTime cell values are normalized invariantly by the reader, separately from parsing locale-specific source strings.
