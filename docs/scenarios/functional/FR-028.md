# FR-028 — Return invalid-record diagnostics

**Requirement:** [FR-028](../../requirements/functional.md)  
**Tracking issue:** [#29](https://github.com/infoconex/RecordSift/issues/29)  
**Priority:** Must  
**Verification status:** Planned — diagnostic unit-contract tests added; end-to-end importer/validation acceptance remains unverified.

## Purpose

Errors are useful only when callers can locate the bad data and understand the category.

## Functional requirement

**RecordSift shall:** Return structured diagnostics for invalid records and fields.

## Inputs and outputs

- **Inputs:** Validation or conversion failures, source identifier, logical record location and field metadata.
- **Outputs:** Stable error diagnostic entries containing source, location, code and sanitized message.

## Functional rules

- Include logical record ordinal, source and field name/position when available.
- Preserve sheet and physical row coordinates for XLSX when available.
- Do not expose raw sensitive input values by default.
- Multiple failures for one record remain separate diagnostics without multiplying `RejectedCount`: a data row with any error is counted once.
- Release 0.1 exposes error diagnostics only; any future non-error severity requires a separately versioned contract.
- Source/schema errors have no processed data-row identity and do not increment row-level counters.

## Dependencies and scope

- **Related requirements:** [FR-018](FR-018.md), [FR-022](FR-022.md), [FR-030](FR-030.md), [NFR-006](../non-functional/NFR-006.md), [NFR-008](../non-functional/NFR-008.md).
- **Boundary:** Fatal source errors must remain distinguishable from per-record diagnostics.

## Open design decisions

Define the error-code registry, diagnostic redaction rules and location availability per reader.

## Acceptance scenarios

### FR-028-SC01 — Identify failed records and fields

**Given** an imported row violates a declared validation rule,  
**When** import completes,  
**Then** a structured diagnostic identifies the source, logical row, field and error code.

### FR-028-SC02 — Report multiple independent failures

**Given** one row violates two independent validation rules,  
**When** validation runs,  
**Then** both failures remain available as distinct diagnostics,  
**And** `RejectedCount` increases by one for the affected row, not two.

### FR-028-SC03 — Keep source failures separate from record counters

**Given** a zero-byte CSV is configured to require headers,  
**When** the import fails during header binding,  
**Then** the result includes a source/schema diagnostic,  
**And** no data row is counted as rejected,  
**And** machine-readable outcome status reports failure independently of row-level counters.
