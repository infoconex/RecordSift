# NFR-009 — Avoid unnecessary platform-specific components

**Requirement:** [NFR-009](../../requirements/non-functional.md)  
**Tracking issue:** [#49](https://github.com/infoconex/RecordSift/issues/49)  
**Priority:** Must — release 0.1 quality requirement (later-platform scenarios remain future milestones).  
**Verification status:** Planned — no executable checks have run.

## NFR-009-SC01 — Review platform dependencies

**Given** the baseline is built with selected third-party packages,  
**When** dependencies and APIs are inspected,  
**Then** unnecessary Windows-only integration points are identified and documented.

## NFR-009-SC02 — Verify modern cross-platform migration

**Given** a later portable target framework is introduced,  
**When** the portable test matrix runs on the declared operating systems,  
**Then** imports behave consistently without introducing an Excel or COM dependency.

## Verification notes

Release 0.1 **SC01 review procedure and observed findings** are recorded in the [net48 platform dependency review](../../engineering/platform-dependencies-net48.md). The review inspected production sources, all five production project dependency graphs and pinned packages, plus the existing Windows Office-free and cross-platform architecture-validation workflow steps. No unnecessary first-party Windows-only integration was found in the reviewed import paths. This is a manual dependency inspection supported by existing executable Windows/architecture checks, not a multi-OS runtime certification.

**SC02 remains Planned and unverified.** No portable target framework or declared operating-system execution matrix exists in release 0.1. Its verification is deliberately deferred; issue #49 must remain open, and no compatibility baseline or net48 target is to be changed to claim completion.


Follow the [testing strategy](../../testing/strategy.md). Record the executable test or reviewed procedure and observed evidence separately for each scenario in [traceability](../../testing/traceability.md). Scenarios for future modernized targets cannot be declared verified on the initial .NET Framework baseline.
