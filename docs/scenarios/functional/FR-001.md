# FR-001 — Import CSV files

**Requirement:** [FR-001](../../requirements/functional.md)  
**Tracking issue:** [#2](https://github.com/infoconex/RecordSift/issues/2)  
**Priority:** Must  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Teams regularly receive comma-separated business data and need a reliable import entry point before domain validation can begin.

## Functional requirement

**RecordSift shall:** read a CSV data source as a sequence of logical records suitable for schema mapping and validation.

## Inputs and outputs

- **Inputs:** A CSV source, schema definition, and reader configuration.
- **Outputs:** Parsed logical records integrated with the standard typed import result, or a classified source failure.

## Functional rules

- Respect CSV quoting so delimiters and embedded newlines inside quoted fields do not create extra records or columns.
- Preserve logical record order and do not silently discard source rows.
- A header-only CSV whose headers satisfy the schema is a successful completed import with no data records.
- A zero-byte CSV is a successful completed import when explicitly configured as headerless; it provides no data records.
- A zero-byte CSV requiring a header row is a **failed source/schema import**, not a successfully completed empty import.
- A successful zero-record import provides a human-readable informational outcome message and zero validation errors; the message itself is not a diagnostic.
- Failure to find a required header provides a classified source/schema diagnostic and a human-readable failure message; callers must also be able to inspect a machine-readable success/failure outcome.
- Distinguish malformed CSV source structure from individual field-validation errors.

## Dependencies and scope

- **Related requirements:** [FR-003](FR-003.md), [FR-004](FR-004.md), [FR-006](FR-006.md), [FR-009](FR-009.md), [FR-026](FR-026.md), [FR-028](FR-028.md), [FR-029](FR-029.md).

## Open design decisions

Clarify which CSV quoting/dialect conventions are initially supported and how partially malformed sources are classified. The behavior of blank-line-only, whitespace-only, and byte-order-mark-only files remains to be specified separately. Outcome status/reason identifiers and the precise public result API are implementation decisions; the messages below are illustrative, not a frozen text contract.

## Acceptance scenarios

### FR-001-SC01 — Import a valid CSV file

**Given** a CSV fixture has three valid customer records and a matching schema,  
**When** the CSV file is imported,  
**Then** three correctly typed records are accepted in original order with no validation errors.

### FR-001-SC02 — Import a header-only CSV file

**Given** a CSV file contains a valid header row matching the required schema columns,  
**And** the file contains no data records,  
**And** the importer is configured to expect a header row,  
**When** the CSV file is imported,  
**Then** the outcome is a successful completed import with zero processed, accepted, and rejected records,  
**And** no validation error is reported solely because there are no records,  
**And** the result provides a human-readable informational message equivalent to "Import completed. No data records found."

### FR-001-SC03 — Report malformed CSV quoting

**Given** a CSV file has malformed quoting,  
**When** import is attempted,  
**Then** a structured parsing failure identifies the source and any reliable location information.

### FR-001-SC04 — Preserve quoted values

**Given** a CSV record contains a delimiter or newline inside a properly quoted field,  
**When** the record is imported,  
**Then** the quoted field is parsed without splitting its content into extra columns or records.

### FR-001-SC05 — Import a zero-byte CSV file in headerless mode

**Given** a CSV file contains zero bytes (no headers and no records),  
**And** the importer is explicitly configured for headerless input,  
**When** the CSV file is imported,  
**Then** the outcome is a successful completed import with zero processed, accepted, and rejected records,  
**And** zero validation errors are recorded,  
**And** the result provides an informational message equivalent to "Import completed. Source contains no records."

### FR-001-SC06 — Reject a zero-byte CSV file when headers are required

**Given** a CSV file contains zero bytes (no header row),  
**And** the importer requires a header row matching the configured schema,  
**When** import is attempted,  
**Then** the outcome is a source/schema failure rather than a successful zero-record import,  
**And** a structured missing-header diagnostic identifies the failure without exposing source values,  
**And** the result provides a human-readable failure message equivalent to "Import failed. The CSV file is empty and the required header row is missing."
