## Purpose

Some consumers need the earliest validation failure rather than a full diagnostic list.

## Functional requirement

**RecordSift shall:** Provide an optional fail-fast import mode that stops when the first configured validation error occurs.

## Inputs and outputs

- **Inputs:** Import source, schema, and a fail-fast policy.
- **Outputs:** A partial result or explicit stopped outcome with the failure and actual progress.

## Functional rules

- Stop processing later logical records once the first triggering error is found.
- Preserve source location and first error details.
- Do not label partial processing as successful completion.
- Process all rows normally when no triggering errors occur.

## Dependencies and scope

- **Related requirements:** [FR-029](FR-029.md), [FR-030](FR-030.md), [FR-036](FR-036.md).
- **Boundary:** Should scope; this mode is distinct from the default continue-on-error policy.

## Open design decisions

FR-031 adds an opt-in boolean `failFast` through additive importer and shared Application pipeline overloads. Existing public signatures and the default continue-on-error behavior are unchanged. All ordinary **record-scope errors** trigger fail-fast: required values, field lengths, bounded patterns, typed conversion, ranges, custom record predicates and duplicate identifiers. Source/header/parser errors retain their existing `Failed` outcome independently of the fail-fast setting.

An early validation stop returns new Domain `ImportStatus.Stopped` and `ImportResult.Stopped`, with **at least one record diagnostic** and no source-scope error. ProcessedCount includes the first invalid logical record and excludes subsequent unvalidated rows. AcceptedRecords contains only the validated prefix's accepted typed records; RejectedCount counts the first invalid record once. Only the first error is reported for the stopping row, even when multiple checks in the same validation stage could fail. No later row is converted or validated. A fully valid input returns normal `Completed` status. A stopped result must never be mislabeled as a successful or fatal-source outcome.

**Release boundary:** Current CSV/XLSX readers materialize the bounded source before shared row validation. Fail-fast stops **validation and mapping**, not already completed parsing or workbook loading. Early source I/O termination would require separately approved streaming architecture (FR-034, Future). Caller-owned readers/streams remain open under the existing ownership rules.

A stopped in-memory result is projected as a **version 1.1** JSON report with the same fields and sanitized messages but a new `Stopped` status; unchanged `Completed` and `Failed` results continue producing the exact JSON version 1.0 baseline. See [versioned JSON contract](../../specifications/import-result.md) and [v1.1 stopped schema](../../specifications/schemas/import-result-stopped.schema.json). This release does not yet implement cancellation (FR-032).

## Acceptance scenarios

### FR-031-SC01 — Stop on the first validation failure

**Given** fail-fast processing is selected for a source with a later invalid row,  
**When** import reaches the first failure,  
**Then** subsequent rows are not processed and partial progress is identified.

### FR-031-SC02 — Process all valid rows

**Given** fail-fast mode is selected and every row is valid,  
**When** import completes,  
**Then** all input rows are accepted without premature termination.
