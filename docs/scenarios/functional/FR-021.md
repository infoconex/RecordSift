# FR-021 — Detect duplicate record identifiers

**Requirement:** [FR-021](../../requirements/functional.md)  
**Tracking issue:** [#22](https://github.com/infoconex/RecordSift/issues/22)  
**Priority:** Must  
**Verification status:** Planned — legacy specification-planning metadata **only**, not current execution status. All 2 FR-021 acceptance scenarios are Automated with observed Windows CI evidence in [scenario-to-test traceability](../../testing/traceability.md).

## Purpose

Duplicate identifiers can create invalid imports even when individual fields parse correctly.

## Functional requirement

**RecordSift shall:** Detect repeated configured record identifiers within the scope of an import.

## Inputs and outputs

- **Inputs:** Typed record identifiers, comparison policy and source record locations.
- **Outputs:** Duplicate-record diagnostics or confirmation of distinct identifiers.

## Functional rules

- Compare identifiers using a documented or explicitly configured equality policy.
- Identify the later duplicate record and its identifier field without logging raw sensitive values by default.
- Count a duplicate as one rejected record even if other validation errors also occur.
- Preserve the original accepted record according to the documented duplicate policy.

## Dependencies and scope

- **Related requirements:** [FR-022](FR-022.md), [FR-028](FR-028.md), [FR-030](FR-030.md).
- **Boundary:** Duplicate detection within one import does not imply checking an external database or cross-file history.

## Open design decisions

Resolved by [ADR 0028](../../engineering/decisions/0028-per-import-duplicate-identifiers.md): callers supply a typed selector and optionally an explicit equality comparer (default typed equality); null identifiers are skipped rather than implicitly required; accepted identifiers are tracked only for the current import and the first accepted record wins. Compound keys and external history remain outside release 0.1; memory scales with the number of distinct accepted identifiers within the configured source limit.

## Acceptance scenarios

### FR-021-SC01 — Flag duplicate identifier

**Given** two source records have an equal identifier under the configured equality policy,  
**When** the later record is validated,  
**Then** the duplicate is identified using its source row and identifier field context without exposing raw data by default.

### FR-021-SC02 — Accept unique identifiers

**Given** all source records have distinct configured identifiers,  
**When** validation runs,  
**Then** no duplicate identifier diagnostic is produced.
