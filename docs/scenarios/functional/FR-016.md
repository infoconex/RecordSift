# FR-016 — Support custom field conversion

**Requirement:** [FR-016](../../requirements/functional.md)  
**Tracking issue:** [#5](https://github.com/infoconex/RecordSift/issues/5)  
**Priority:** Should  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Applications need domain-specific conversions beyond built-in primitive parsing.

## Functional requirement

**RecordSift shall:** Allow callers to provide a converter for a declared field.

## Inputs and outputs

- **Inputs:** A registered converter, source value, field metadata and culture/options.
- **Outputs:** A typed converted value or a field-specific conversion diagnostic.

## Functional rules

- Invoke the configured converter deterministically for its declared field.
- Preserve source location when a converter rejects data.
- Do not let one record-specific conversion failure corrupt other accepted records.
- Document how converter exceptions are surfaced without exposing sensitive input.

## Dependencies and scope

- **Related requirements:** [FR-010](FR-010.md), [FR-011](FR-011.md), [FR-018](FR-018.md).
- **Boundary:** Should feature; no general-purpose script execution or unsafe dynamic evaluation.

## Open design decisions

Decide converter registration precedence, thread safety and exception policy.

## Acceptance scenarios

### FR-016-SC01 — Invoke a registered converter

**Given** a configured custom converter handles a supported source field,  
**When** the field is imported,  
**Then** the converter result is assigned to its target property.

### FR-016-SC02 — Report custom conversion failure

**Given** a registered converter rejects an invalid source value,  
**When** import runs,  
**Then** a structured field-specific diagnostic is returned without corrupting other records.
