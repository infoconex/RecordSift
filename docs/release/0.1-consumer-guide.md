# RecordSift release 0.1 candidate consumer guide

The intended release 0.1 platform is Windows with the .NET Framework 4.8 runtime; compilation requires the .NET Framework 4.8 targeting pack and C# 7.3-compatible tools. No Excel installation, COM automation or external service is required for imports. NuGet access during initial package restoration may require Internet connectivity.

## Obtaining the candidate

There is no published NuGet distribution. From a clean Windows source checkout (Visual Studio Developer PowerShell or compatible MSBuild environment), generate the local unpublished candidate using:

```powershell
nuget restore .\RecordSift.sln -NonInteractive -PackagesDirectory packages -ConfigFile NuGet.Config
msbuild .\RecordSift.sln /m /t:Rebuild /p:Configuration=Release '/p:Platform=Any CPU'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_release_candidate.ps1 -OutputDirectory C:\Temp\RecordSift-Internal-Candidate
```

For a standalone install, use the local feed plus nuget.org for the package's declared dependencies:

```powershell
nuget install RecordSift -Version 0.1.0-rc.1 -Framework net48 -OutputDirectory C:\Temp\RecordSift-Consumer -Source 'C:\Temp\RecordSift-Internal-Candidate;https://api.nuget.org/v3/index.json' -NonInteractive -NoCache
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_clean_consumer.ps1 -CandidateDirectory C:\Temp\RecordSift-Internal-Candidate
```

To perform a pre-publication check against the intended **stable 0.1.0 package identity**, build into a **different temporary folder**, then install it only from the local feed:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_release_candidate.ps1 -OutputDirectory C:\Temp\RecordSift-Internal-Stable -PackageVersion 0.1.0
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_clean_consumer.ps1 -CandidateDirectory C:\Temp\RecordSift-Internal-Stable -PackageVersion 0.1.0
```

The stable `RecordSift.0.1.0.nupkg` is **not published**, even if all local checks pass. The installed assembly versions stay at `0.1.0.0` for both candidate identities. Do not upload to a feed or create a public release without separate authorization.

The built nupkg includes five RecordSift DLLs, XML docs, a README, the owner-approved MIT LICENSE and THIRD-PARTY-NOTICES.md. The package metadata declares the SPDX `MIT` license expression. The automated consumer additionally compiles and runs source outside the solution against only installed assemblies. The license decision in #186 is approved; this internal candidate is nevertheless **not authorized for publication**. Release promotion to `main` and package upload require a separate explicit authorization.

## NuGet installation and dependencies

Use the local candidate directory as a NuGet package source, install package RecordSift version 0.1.0-rc.1 targeting net48 and allow nuget.org as an additional vendor dependency feed. Package-managed assemblies are RecordSift.Domain, RecordSift.Application, RecordSift.Infrastructure.Csv, RecordSift.Infrastructure.Xlsx and RecordSift.Infrastructure.Reporting. CsvHelper 33.1.0 and ExcelDataReader 3.9.0 are direct third-party dependencies; NuGet resolves their transitive graph. Do not simply copy the five RecordSift DLLs without their runtime dependencies.

## Usage and verification

The root README shows complete CSV and XLSX examples using ImportSchema, ExpectedColumn, PropertyMappingSchema, SourcePropertyMapping, PrimitivePropertyMapper<T>, CsvImporter<T> / CsvRecordReaderAdapter and XlsxImporter<T> / XlsxWorksheetReaderAdapter. CSV supports explicit delimiter, header policy or positional binding, encoding and bounded decoded characters; XLSX supports worksheet name selection and byte/row/column/cell-character limits. Source streams belong to callers. Use explicit CultureInfo for deterministic primitive conversions. Required, length, range, pattern, duplicate ID, caller-defined conversion, and custom cross-field predicate validation use existing domain-owned rules.

TypedImportResult<T> exposes Status, Summary, AcceptedRecords and ordered Diagnostics. Completed may contain rejected records; Failed represents a source-level failure. Stopped reflects opt-in fail-fast partial processing; Canceled is cooperative, reports accurate prefix counts and does not necessarily interrupt bounded eager source reading. Record diagnostics have stable codes and optional source/row/field/worksheet/physical-position metadata.

Use JsonImportResultSerializerAdapter.Serialize(result) for versioned JSON, ReadableImportResultFormatterAdapter.Format(result) for invariant readable text and CsvImportResultSerializerAdapter.Serialize(result) for escaped diagnostic CSV. The JSON schema version is independent of the package version: Completed/Failed emit 1.0, Stopped 1.1, Canceled 1.2. Reports omit accepted CLR records. A consumer determines how and where to store report strings.

## Supported scope and safety

Release 0.1 supports Windows/net48 only. There is no committed Linux/macOS, modern .NET, asynchronous, streaming, fixed-width, severity configuration or caller-defined report-layout support. Import source IDs, field names and worksheet identifiers should be opaque and nonsensitive. Default reports redact rooted source paths, not arbitrary caller-selected identifiers. **Diagnostic CSV is intended for machine-to-machine interchange, not safe spreadsheet display.** The exporter preserves original metadata such as source IDs, column names and worksheet names, including formula-like text beginning with `=`, `+`, `-`, `@`, tabs and embedded CR/LF. Quoting and doubled quotes prevent CSV field-boundary corruption but do **not** prevent Excel or another spreadsheet from interpreting a field as a formula. Do not open diagnostic CSV containing untrusted identifiers directly in spreadsheet software. If spreadsheet presentation is needed, import every column as text or apply a separately verified spreadsheet-specific transformation and accept that it changes the parsed data. See [FR-038's exact interchange contract](../scenarios/functional/FR-038.md) and the [OWASP CSV Injection guidance](https://owasp.org/www-community/attacks/CSV_Injection). XLSX macros/formulas are not evaluated by the import reader. The internal XLSX ZIP preflight enforces a maximum of 512 entries and total declared **and measured decompressed** bytes limited to the smaller of 64 MiB or 32 times the caller's compressed-byte limit. XML shared-string preflight rejects DTDs/external entities and excessive count/capacity hints above one million items before the vendor parser initializes. These are bounded-input safeguards, **not** a fixed memory/CPU ceiling; the workbook and accepted records are processed eagerly, and cancellation during that parsing is not immediate. Choose conservative maxBytes and XlsxReadLimits values when accepting hostile documents. Consult the [security assessment and accepted residual risks](../engineering/release-0.1-security-assessment.md). The owner-approved MIT license appears in the package, but release promotion and public package publication remain separate authorization gates.
