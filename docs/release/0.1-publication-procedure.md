## 5. Verify the actual published package (different from local preflight)

After NuGet indexes the version, independently install **`RecordSift 0.1.0` from nuget.org alone** into a fresh Windows/net48 C# 7.3 consumer, not from the local prepublication feed. From the exact published `v0.1.0` source checkout, run:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_clean_consumer.ps1 -FromNuGetOrg -PackageVersion 0.1.0 -ExpectedSourceCommit '<40-character-release-SHA>'
```

This command uses **only nuget.org** as the package source, installs into a fresh isolated folder, checks the embedded exact Git source commit, MIT notices and eleven pinned vendor dependencies, compiles a separate C# 7.3 Windows/net48 consumer, and executes real CSV/XLSX imports and diagnostic reports. Separately inspect all five assemblies and XML docs, the public license/notices and effective package repository commit. Run `nuget verify -Signatures` (or the supported signature-verification equivalent) against the nuget.org-downloaded package.

**Important:** nuget.org repository-signs hosted packages and can modify the archive by adding a signature. A downloaded `.nupkg` may therefore have a different *whole-file* SHA256 from the prepublication upload. Preserve and report **both** hashes; compare normalized package contents/metadata and individual assembly hashes, and validate the NuGet repository signature rather than declaring corruption based solely on the changed archive SHA256.
