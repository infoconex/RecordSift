# FR-007 — Read fixed-width text files

**Requirement:** [FR-007](../../requirements/functional.md)  
**Tracking issue:** [#7](https://github.com/infoconex/RecordSift/issues/7)  
**Priority:** Future  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

A future release may need to consume positional text exports common in enterprise systems.

## Functional requirement

**RecordSift shall:** Support field extraction from fixed-width records using declared offsets and widths.

## Inputs and outputs

- **Inputs:** Fixed-width records and field offset/length schema.
- **Outputs:** Mapped fields or structural diagnostics identifying incomplete records.

## Functional rules

- Extract the declared spans without shifting adjacent fields.
- Do not silently truncate fields whose declared span exceeds the record length.
- Preserve significant padding until a configured field conversion removes it.

## Dependencies and scope

- **Related requirements:** [FR-008](FR-008.md), [FR-009](FR-009.md), [FR-028](FR-028.md).
- **Boundary:** Deferred Future requirement; not included in release 0.1.

## Open design decisions

Choose character offsets vs byte offsets and whether line endings are data.

## Acceptance scenarios

### FR-007-SC01 — Map fields by offset and length

**Given** a fixed-width fixture and schema define field offsets and widths,  
**When** a record is imported,  
**Then** fields map to their intended values without silently trimming significant characters.

### FR-007-SC02 — Report undersized records

**Given** a fixed-width record is shorter than a required field extent,  
**When** import is attempted,  
**Then** a row-specific structural diagnostic is returned.
