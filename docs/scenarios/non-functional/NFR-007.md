# NFR-007 — Enforce configurable input resource limits

**Requirement:** [NFR-007](../../requirements/non-functional.md)  
**Tracking issue:** [#47](https://github.com/infoconex/RecordSift/issues/47)  
**Priority:** Must — release 0.1 quality requirement (later-platform scenarios remain future milestones).  
**Specification status:** Maintained — normative behavior; per-scenario verification and observed CI evidence are recorded in the [traceability matrix](../../testing/traceability.md).

## NFR-007-SC01 — Enforce a configured maximum

**Given** the input exceeds a documented file, row, or supported workbook limit,  
**When** import runs with that limit,  
**Then** processing fails predictably with a limit-specific diagnostic rather than unbounded consumption.

## NFR-007-SC02 — Accept input at an inclusive limit

**Given** a source meets but does not exceed a configured bound,  
**When** import runs,  
**Then** no limit error is returned solely because of the boundary value.

## Verification notes

Release 0.1 verification uses real CSV and XLSX importers. Controlled boundaries include the decoded CSV character budget (including the maximum supported `int` value), compressed XLSX bytes, field columns, cell text length, and the ZIP preflight's declared expanded-byte budget. Exceeded limits must atomically return `SOURCE_LIMIT_EXCEEDED`, with a caller-owned source left open. The exact CSV character and compressed workbook byte boundaries must be inclusive.

The fixed ZIP package-entry and expanded-byte guards are internal defense-in-depth, **not** caller-configurable limits. Small controlled fixtures test logical boundaries, not measured peak memory or protection against every hostile archive implementation. The maximum-integer CSV budget regression corrects overflow in a bounded-read probe without changing the public API or defaults.
