# FR-030 — Provide import processing summary

**Requirement:** [FR-030](../../requirements/functional.md)  
**Tracking issue:** [#31](https://github.com/infoconex/RecordSift/issues/31)  
**Priority:** Must  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Consumers need trustworthy totals for monitoring and deciding whether to accept an import.

## Functional requirement

**RecordSift shall:** Return a row-oriented summary of processed, accepted, rejected and warning-bearing records, with a separate machine-readable import outcome.

## Inputs and outputs

- **Inputs:** The completed import's accepted records and accumulated diagnostics.
- **Outputs:** Internally consistent summary counters and completion/failure state.

## Functional rules

- For completed imports, Processed equals Accepted plus Rejected.
- Count each rejected logical record once even if several errors occur.
- `RejectedCount` counts each distinct logical data row with one or more error-level record diagnostics **once**; it is the count of rows with errors.
- `WarningRowCount` counts each distinct logical data row with one or more warning-level diagnostics **once**.
- A rejected row may also have warnings; `WarningRowCount` can overlap with `RejectedCount` and must not be added when calculating `ProcessedCount`.
- The JSON representation of these counters follows the [versioned import result contract](../../specifications/import-result.md). Individual diagnostics remain available for detailed inspection. Avoid ambiguous aggregate `ErrorCount` or `WarningCount` names; any future count of diagnostic occurrences must be separately and explicitly named.
- Warning-only rows count as accepted under the documented default contract.
- Completed zero-record imports retain Processed = Accepted = Rejected = 0, without generating validation errors solely because no records were found.
- A source/schema failure that occurs before the first record also has zero processed records but a **failed** outcome and a separate source-level diagnostic. Source-level diagnostics do **not** increment either `RejectedCount` or `WarningRowCount`; zero counters never imply success.

## Dependencies and scope

- **Related requirements:** [FR-025](FR-025.md), [FR-027](FR-027.md), [FR-028](FR-028.md), [FR-029](FR-029.md), [FR-036](FR-036.md).
- **Boundary:** Elapsed-time metrics and instrumentation are not implied by this requirement.

## Open design decisions

The [version 1.0 JSON contract](../../specifications/import-result.md) now proposes the initial `Completed`/`Failed` states and exact JSON counter names. The in-memory .NET API, future cancellation/partial states and diagnostic-code registry remain decisions for implementation. The row-based counting semantics are required regardless of eventual public API type names.

## Acceptance scenarios

### FR-030-SC01 — Summarize processed and rejected rows

**Given** a completed import contains accepted records and rejected records with one or more errors,  
**When** the result summary is calculated,  
**Then** `ProcessedCount` equals `AcceptedCount` plus `RejectedCount`,  
**And** `RejectedCount` counts each row with one or more errors once, not the number of individual error diagnostics,  
**And** `WarningRowCount` counts each row with one or more warnings once.

### FR-030-SC02 — Count warning-only records correctly

**Given** an otherwise valid record produces warnings but no errors,  
**When** the import summary is calculated,  
**Then** the record remains accepted,  
**And** `WarningRowCount` includes the row once, regardless of how many warnings it has,  
**And** warnings do not increase `RejectedCount`.

### FR-030-SC03 — Distinguish a completed empty import from a missing-header failure

**Given** one import result represents a valid header-only CSV with no data rows,  
**And** another result represents a zero-byte CSV for which headers were required,  
**When** the results' status and counters are inspected,  
**Then** both have zero processed, accepted, and rejected records,  
**And** the first outcome is Completed with no error diagnostics,  
**And** the second outcome is Failed with a source/schema diagnostic,  
**And** a caller can distinguish them without examining the human-readable message.

### FR-030-SC04 — Count multiple errors in one row once

**Given** a file contains five processed rows,  
**And** two rows are invalid, one of which has three error-level diagnostics,  
**When** the import summary is calculated,  
**Then** `ProcessedCount` is 5, `AcceptedCount` is 3 and `RejectedCount` is 2,  
**And** the three individual errors remain available in the diagnostics collection,  
**And** they do not inflate `RejectedCount` to 4.

### FR-030-SC05 — Count rows with warnings once, including rejected rows

**Given** one accepted row has two configured warnings,  
**And** one rejected row has an error and a warning,  
**And** the other processed rows have no warnings,  
**When** the import summary is calculated,  
**Then** `WarningRowCount` is 2,  
**And** the rejected row is counted in both `RejectedCount` and `WarningRowCount`,  
**And** `ProcessedCount` still equals `AcceptedCount` plus `RejectedCount`.
