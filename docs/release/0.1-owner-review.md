## Security and owner risk decisions

**Mitigated in RecordSift, not claimed fixed upstream:** SEC-XLSX-001 ZIP actual expanded-byte accounting ([PR #211](https://github.com/infoconex/RecordSift/pull/211)); SEC-XLSX-002 XML shared-string capacity hint/item preflight ([PR #213](https://github.com/infoconex/RecordSift/pull/213)); SEC-XLSX-003 binary workbook relationship preflight ([PR #219](https://github.com/infoconex/RecordSift/pull/219)). Their negative and positive XLSX regressions and additional CSV, regex, diagnostic secrecy, partial stream read, encoding and ownership scenarios are recorded in the [security assessment](../engineering/release-0.1-security-assessment.md).

**Residual operational risks requiring personal owner assessment:** eager parser/cancellation latency; non-hard process memory/CPU caps, downstream ExcelDataReader allocations and caller-selected large input budgets; per-match rather than cumulative regex time limits; arbitrary caller-defined validation callbacks; caller-controlled diagnostic metadata; diagnostic CSV formula interpretation by spreadsheet applications; dependency supply-chain exposure; imperfect coverage of adversarial inputs. [Issue #200](https://github.com/infoconex/RecordSift/issues/200) records a **limited owner acceptance** of machine-interchange-only CSV semantics, not blanket risk or publication approval. The separate upstream ExcelDataReader investigation remains independent; do not assert vendor fixes without verification and do not make disclosure completion a release prerequisite unless a concrete unresolved release-blocking RecordSift risk emerges.

## Promotion and rollback procedure (not permission)

1. When exact post-reconciliation integration HEAD has all four required successful jobs and has no unresolved blocking issue, prepare **new main-based staging commit** with the *identical integration Git tree*, parented to the current main commit. Confirm tree SHAs match exactly, and create a **Draft** main-targeted PR containing this review package. Do not modify, close or merge #209.
2. Verify all four required **main-targeted PR HEAD** jobs. Owner performs their second-pass review and records explicit dated GO for exactly that integration SHA/staging HEAD. Only then, under a **separate owner instruction**, mark ready and perform **squash-only** promotion.
3. After authorized promotion, compare promoted main tree against the approved integration tree and run all four job checks on the new main SHA. If validation fails, halt publication; resolve through separately reviewed corrective commits/revert rather than treating an earlier green run as sufficient.
4. **Public distribution is a different decision:** before any tag, GitHub Release or NuGet upload, authorize the exact artifact/version/channel, rebuild/inspect the stable package at promoted source, record retained SHA256 and license/dependency audit, and verify independently installed published-package behavior. Do not overwrite a defective published package; halt distribution, record hashes/affected versions, and plan a reviewed corrective version and consumer advisory.
