# FR-037 — Support readable error summaries

**Requirement:** [FR-037](../../requirements/functional.md)  
**Tracking issue:** [#38](https://github.com/infoconex/RecordSift/issues/38)  
**Priority:** Must  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

A human-readable explanation helps developers diagnose failed imports without inspecting raw structures.

## Functional requirement

**RecordSift shall:** Produce concise plain-language summaries of an existing import result.

## Inputs and outputs

- **Inputs:** In-memory summary counters and sanitized diagnostics.
- **Outputs:** A readable summary that accurately describes accepted/rejected records and reasons.

## Functional rules

- Explain failures using available row and field context.
- Do not include raw sensitive source values by default.
- Accurately describe clean imports and zero-row results.
- Derive output from the result without reopening the source.

## Dependencies and scope

- **Related requirements:** [FR-028](FR-028.md), [FR-030](FR-030.md), [FR-036](FR-036.md), [NFR-008](../non-functional/NFR-008.md).
- **Boundary:** Should not be treated as localized UI presentation or a substitute for structured diagnostics.

## Open design decisions

Determine whether formatting is invariant English or culture/localization-configurable.

## Acceptance scenarios

### FR-037-SC01 — Explain failed rows

**Given** an import result contains invalid rows,  
**When** a human-readable summary is requested,  
**Then** the summary identifies failed row locations and reasons while omitting raw sensitive values.

### FR-037-SC02 — Summarize a clean import

**Given** a result has no errors or warnings,  
**When** a summary is requested,  
**Then** the summary accurately communicates successful processing without invented failures.
