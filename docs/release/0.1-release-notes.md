# RecordSift 0.1.0 — first stable release notes

**Platform:** Windows and .NET Framework 4.8. **Source:** [infoconex/RecordSift](https://github.com/infoconex/RecordSift). **License:** MIT, Copyright (c) 2026 Infoconex. **Language baseline:** C# 7.3. **Release tag:** `v0.1.0` points to the exact `main` release-source commit when created. The package and tag should not be represented as published until their URLs are verified.

## What's included

RecordSift imports CSV (headers or positional binding, configurable delimiter and encoding) and XLSX (first or selected named worksheet). It maps source fields to typed records with required columns, aliases, defaults and culture-aware primitive conversion. It validates values and records using length, range, required, duplicate, bounded regex and cross-field rules and returns structured diagnostics. Outputs include structured import results, versioned JSON, readable text summaries and lossless diagnostic CSV.

The distribution packages five .NET Framework 4.8 assemblies with XML API documentation: `RecordSift.Domain`, `RecordSift.Application`, `RecordSift.Infrastructure.Csv`, `RecordSift.Infrastructure.Xlsx`, and `RecordSift.Infrastructure.Reporting`. It declares exact versions for eleven NuGet runtime dependencies including CsvHelper 33.1.0 and ExcelDataReader 3.9.0. Microsoft Office is not required, and no external service is required for runtime parsing.

## Security and operational limits

The XLSX adapter preflights ZIP entries (512 maximum), declared and actual decompressed byte budgets (at most 64 MiB and 32 times the caller's compressed-byte budget), shared-string count/hints (one million maximum), prohibited DTDs/external XML entities and binary spreadsheet relationships. These are RecordSift-level mitigations; they are **not** proof that underlying third-party parsers have no vulnerabilities. Relevant regression suites also cover malformed CSV/XLSX inputs, Unicode budgets, regex timeouts and error-report redaction.

Data processing is synchronous and can eagerly allocate memory. Caller-supplied size limits, worksheet constraints and validation budgets are essential for untrusted input, but **no absolute process heap/CPU bound or immediate cancellation guarantee** is provided. Caller callbacks and metadata may require application-level safety controls. Diagnostic CSV is intended for **machine interchange**, not for direct opening in spreadsheet software: untrusted identifiers can be interpreted as formulas. Use text-only import or a separately verified spreadsheet-safe export step. Only Windows/net48 is supported; async, streaming and platform expansion are future work.
