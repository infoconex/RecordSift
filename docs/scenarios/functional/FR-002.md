# FR-002 — Import XLSX workbooks

**Requirement:** [FR-002](../../requirements/functional.md)  
**Tracking issue:** [#6](https://github.com/infoconex/RecordSift/issues/6)  
**Priority:** Must  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Organizations need to validate tabular workbook data without installing Excel.

## Functional requirement

**RecordSift shall:** Read supported `.xlsx` cell data as logical records suitable for the common import pipeline.

## Inputs and outputs

- **Inputs:** An XLSX workbook source, schema, and worksheet-selection option.
- **Outputs:** Records with worksheet/row provenance or a classified source-level error.

## Functional rules

- Import stored cell data without automating Excel.
- Maintain record order within the selected worksheet.
- Preserve worksheet name and source row coordinates for diagnostics.
- Report corrupt or unreadable workbooks as source failures, not successful zero-row imports.

## Dependencies and scope

- **Related requirements:** [FR-005](FR-005.md), [FR-009](FR-009.md), [FR-026](FR-026.md), [FR-028](FR-028.md), [NFR-003](../non-functional/NFR-003.md), [NFR-008](../non-functional/NFR-008.md).
- **Boundary:** Editing workbooks, executing macros and formula recalculation are out of scope.

## Open design decisions

Define how formula cached values, blank rows and merged cells are handled.

## Acceptance scenarios

### FR-002-SC01 — Read a valid worksheet

**Given** an XLSX fixture contains typed customer data and a matching schema,  
**When** the workbook is imported,  
**Then** records are typed correctly and preserve worksheet name and row provenance.

### FR-002-SC02 — Reject an unreadable workbook

**Given** the provided file is not a valid XLSX workbook,  
**When** import is attempted,  
**Then** a source-level failure is reported without presenting a successful empty import.
