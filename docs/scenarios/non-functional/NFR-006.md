# NFR-006 — Provide actionable malformed-input failures

**Requirement:** [NFR-006](../../requirements/non-functional.md)  
**Tracking issue:** [#46](https://github.com/infoconex/RecordSift/issues/46)  
**Priority:** Must — release 0.1 quality requirement (later-platform scenarios remain future milestones).  
**Verification status:** Planned — no executable checks have run.

## NFR-006-SC01 — Classify corrupt input

**Given** an XLSX or CSV source is unreadable or malformed,  
**When** import is attempted,  
**Then** a clear source-level failure is returned without a misleading successful zero-row result.

## NFR-006-SC02 — Preserve error provenance safely

**Given** input contains a parsing error and potentially sensitive values,  
**When** the error is reported,  
**Then** the source location and error category are available without exposing raw sensitive content by default.

## Verification notes

Release 0.1 verification exercises real CSV and XLSX adapters through typed public importers. Malformed CSV quoting after an otherwise valid record, an I/O-failing CSV reader, and corrupt XLSX content must each fail at source scope, discard all partially accepted records, retain only reliable physical locations, and emit resource-backed messages without echoing raw source values or file paths. These checks do not guarantee an exact location for unreadable streams or an invalid ZIP package.


Follow the [testing strategy](../../testing/strategy.md). Record the executable test or reviewed procedure and observed evidence separately for each scenario in [traceability](../../testing/traceability.md). Scenarios for future modernized targets cannot be declared verified on the initial .NET Framework baseline.
