# RecordSift 0.1 — release candidate notes (not published)

This is an internal 0.1.0-rc.1 candidate of a Windows-only .NET Framework 4.8 / C# 7.3 library, not a public release or final 0.1.0 package.

## Features in the accepted release scope

CSV with configurable delimiter, headers, positional bindings and encoding; XLSX with worksheet selection; typed schema mapping, aliases, default values, primitive/caller-provided conversion; length, range, required, duplicate, bounded pattern and cross-field/record validation; synchronous import with fail-fast and cooperative cancellation; stable structured results and diagnostic codes; JSON schema-versioned reports, invariant readable summaries, escaped deterministic CSV diagnostics.

## Baselines and versions

All 25 Must and eight targeted Should functional requirements, plus ten NFRs for Windows/net48, passed acceptance at the functional completion milestone. Windows CI at integration commit 7850680619cd1652182d50ac7485a59c55c233a8 passed 379 NUnit cases and seven JSON golden compatibility fixtures, and validated the compiled public API baseline.

This explicitly approved internal identity change is recorded in the compiled net48 API baseline. There is no previously published stable binary compatibility claim.

## Known limitations

Only Windows/net48 is supported. Asynchronous and streaming APIs and configurable diagnostic severity are Future features. XLSX preflight bounds archive entries (512), declared and actual decompression (64 MiB or 32 times the compressed-byte budget), and shared-string item/count hints (one million). XML preflight prohibits DTDs and external entities. Relationship-linked binary workbook, worksheet, styles and shared-string parts (unsupported XLSB/BIFF hybrids) are rejected before third-party parsing; unrelated binary attachments are not rejected solely for having a `.bin` extension. These controls do not establish a fixed maximum process-memory or CPU footprint; set conservative caller budgets for untrusted inputs. See the [security register](../engineering/release-0.1-security-assessment.md). Imported results and diagnostics may use memory proportional to bounded input. Import cancellation does not interrupt all eager bounded source I/O. XLSX macros and formula evaluation are not performed. Accepted record values are not included in default reports. Caller-controlled identifiers may contain sensitive strings; diagnostic CSV is a **lossless machine-interchange format, not a spreadsheet-safe export**. Untrusted `SourceId`, `Field` and `Worksheet` metadata can begin with formula-like characters; RFC-style CSV quoting preserves data but does not neutralize spreadsheet execution. Spreadsheet consumers must import values as text or use separately verified formula-neutralization before opening untrusted reports. The release owner accepted the residual spreadsheet-formula interpretation risk for this machine-interchange-only CSV contract in [completed issue #200](https://github.com/infoconex/RecordSift/issues/200). This acceptance does **not** authorize a release tag, GitHub Release, NuGet publication, or any other public distribution; those require a separate publication GO.
