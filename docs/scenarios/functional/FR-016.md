# FR-016 — Support custom field conversion

**Requirement:** [FR-016](../../requirements/functional.md)  
**Tracking issue:** [#5](https://github.com/infoconex/RecordSift/issues/5)  
**Priority:** Should  
**Verification status:** Planned — executable tests have not been implemented.

## Purpose

Applications need domain-specific conversions beyond built-in primitive parsing.

## Functional requirement

**RecordSift shall:** Allow callers to provide a converter for a declared field.

## Inputs and outputs

- **Inputs:** A registered converter, source value, field metadata and culture/options.
- **Outputs:** A typed converted value or a field-specific conversion diagnostic.

## Functional rules

- Invoke the configured converter deterministically for its declared field.
- Preserve source location when a converter rejects data.
- Do not let one record-specific conversion failure corrupt other accepted records.
- Document how converter exceptions are surfaced without exposing sensitive input.

## Dependencies and scope

- **Related requirements:** [FR-010](FR-010.md), [FR-011](FR-011.md), [FR-018](FR-018.md).
- **Boundary:** Should feature; no general-purpose script execution or unsafe dynamic evaluation.

## Open design decisions

Release 0.1 uses explicit, format-neutral `FieldConversionRule` instances registered by canonical exact-case source-field identifiers on `PrimitivePropertyMapper<T>`. The optional rule supersedes primitive conversion for that field only; all other mapped fields retain the existing culture-controlled converter. A single rule per mapped field is allowed; null, unknown and duplicate registrations fail during mapper construction.

A caller delegate receives the raw field string and a read-only copy of the explicit conversion culture and must return a value assignable to the declared CLR property (or null for nullable/reference properties). Domain-specific target types such as Guid are supported only when a rule is explicitly configured. A converter for a defaulted optional field is also checked against its default value during mapper construction, then invoked for imported rows using the same declared culture.

For input-specific converter failures (including user delegate exceptions and wrong return types), the Application mapper discards exception details and returns the standard source-field `CONVERSION_FAILED` diagnostic with physical location; other records continue normally. Cancellation requests, out-of-memory conditions and thread-abort conditions are not misclassified as data failures. Rules and culture references are snapshotted, but callers must make stateful delegate implementations thread-safe when sharing them concurrently. No input-supplied code, scripts, or parser types are evaluated.

## Acceptance scenarios

### FR-016-SC01 — Invoke a registered converter

**Given** a configured custom converter handles a supported source field,  
**When** the field is imported,  
**Then** the converter result is assigned to its target property.

### FR-016-SC02 — Report custom conversion failure

**Given** a registered converter rejects an invalid source value,  
**When** import runs,  
**Then** a structured field-specific diagnostic is returned without corrupting other records.
